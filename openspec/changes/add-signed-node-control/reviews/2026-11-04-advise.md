## Blind take

Written before opening design.md or tasks.md, from proposal Why, the delta, the living holder requirement, and the cited code.

1. Pin destination verification to its own node identity and owner-verified authority; entry-hop assertions and transport identity cannot supply authority.
2. Preserve the original canonical request, raw token, holder key, and possession signature through both adapters; execution must use the verified operation and arguments.
3. Keep holder injection exclusively in the grant verifier, including rejection of holder-headed rules waiting on verifier time or holder facts.
4. Reserve the complete ReplayObligation durably before effects, with a single atomic winner across concurrent requests and ledger users.
5. Refuse missing, corrupt, unreadable, or unsuccessfully persisted ledger state; initialization must be explicit and separate from request handling.
6. Pin crash behavior between reservation, execution, and receipt: an uncertain result must never release a reservation for another execution.
7. Preserve the authenticated-time high-water floor and define the destination challenge's provenance and replay lifetime across restarts.
8. Pin receipt array fields, canonical encoding, destination signer identity, and outcome meaning so a receipt cannot be substituted between requests.
9. Bound envelope parsing and transport work; add the admin ALPN without changing existing tunnel, gossip, capability, or probe behavior.
10. Accept durable at-most-once dispatch at the cost of a consumed request after a crash; refuse an exactly-once completion promise without transactional effects.

## Comparison and steelman

The author has answered the core direction correctly: one destination verifier, the complete replay tuple, a file-backed ledger that refuses missing state, exact canonical request bytes, a distinct admin ALPN, destination-signed receipts, and local transport tests without radio effects. The landed holder rule check in `engine.rs:470` implements the living requirement; this change need not redesign it. Existing meshd router branches (`mjolnir-meshd.rs:1001–1025`) also offer a straightforward place for a separate handler.

The strongest case for acceptance is that this is a deliberately small adapter-and-ledger slice: the grant library already owns signatures and policy, and implementation can choose ordinary locking and serialization details. I agree that no new database, challenge service, transactional radio executor, or fleet provisioning project is warranted. Nevertheless, the omissions below determine observable security and recovery behavior, rather than merely implementation technique. The existing test list exercises sequential happy/refusal paths and would not distinguish unsafe choices.

## Owed before act

1. **Define the reservation lifecycle and prove it survives races and restart.** `design.md:9,18` says durable reservation before execution but does not define atomic check-and-reserve, ledger ownership/locking, the durable completion point, or failure after reservation. Two callers must not both pass an absence check. A reservation must remain consumed after execution failure, cancellation, lost reply, or restart; persistence failure must prevent execution. Pin explicit first-time initialization separately from normal open so the missing-file refusal is implementable. A single writer with exclusive ownership is sufficient; no particular storage algorithm is demanded. Add concurrent duplicate, reopen/replay, failed-persist, and crash-after-reserve tests. Clarify at-most-once dispatch versus guaranteed completion, and correct proposal's “ledger has no reservation → operation does not run” journey, which contradicts the valid first-use scenario.

2. **Finish the shared wire contract.** `design.md:17–20` chooses names and conceptual receipt contents, but neither defines the envelope nor pins receipt array order, field types/lengths, operation arguments, outcome codes/payload, and signature packaging. `verify_holder_proof` (`lib.rs:525`) requires four separate inputs: canonical request, original raw token, holder key, and signature. Define how the same bounded byte envelope carries these over HTTP and a framed iroh stream, including malformed/trailing/oversized input refusal and transport timeout behavior. Pin how hello reaches the destination and returns its receipt unchanged. Add golden encoding/signature vectors and a local HTTP→entry→iroh→destination round trip with the entry lacking the destination signing key; authenticate the receipt against the requested destination, not a key supplied only by the response.

3. **Pin the destination context and execution seam.** `authorize` (`engine.rs:289`) checks the request node against the supplied authority, not against the running endpoint; `AuthorityBook::verified_authority` (`record.rs:788`) derives that authority node from the signed control record's subject. The adapter must separately enforce the local destination binding and obtain authority/owner trust, authenticated time, high-water state, and the existing node signing key from destination-owned context. Define restart handling for the time floor and whether `target_challenge` is a validated destination challenge or only an opaque replay component; the current engine merely copies it into the obligation. An explicitly installed context that refuses while absent is sufficient. Also pin which existing operations this slice dispatches, how the executor receives only verified arguments, and what a successful outcome means. `ApplyNetworkPlan` contains a plan digest, not the plan body (`lib.rs:109`); if it is supported here, resolved plan bytes and revision must match those signed arguments. A bounded injected executor with local test effects is acceptable. Add wrong-local-node, absent-context, and verified-argument dispatch tests, and keep holder-fact/rule refusal covered through the destination path.

These are contract amendments for the author, not a competing design or a request to implement additional product scope. Fresh advise remains unchecked until the amended contract is independently accepted.
