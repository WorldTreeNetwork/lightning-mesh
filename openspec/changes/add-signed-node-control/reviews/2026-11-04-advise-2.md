## Blind take

Written before opening design.md, tasks.md, or the prior review; based on proposal Why, the current delta, the living holder spec, and the two cited source files.

1. Pin execution as at-most-once per ReplayObligation, including the crash window after reservation and before execution.
2. Refuse automatic ledger recreation; explicit initialization must not overwrite an existing ledger or silently reset replay history.
3. Pin one atomic check-and-reserve owner and durable persistence before any executor side effect, including concurrent presentations.
4. Persist the authorization time floor with replay state, reload it on restart, and refuse storage failure before execution.
5. Keep canonical request bytes, exact raw token bytes, holder key, and holder signature separate through verification.
6. Pin envelope field types, order, version, canonicality, size limits, and transport framing so HTTP and iroh cannot reinterpret the request.
7. Pin signed receipt bytes and request correlation; a valid signature alone does not establish that the receipt belongs to the expected obligation.
8. Refuse caller-supplied authority, time, local-node identity, or signing key as destination context; check the actual local target before reservation.
9. Dispatch only the verified closed operation and arguments, with ApplyNetworkPlan content and revision checked against the signed commitment.
10. Accept the availability tradeoff of permanently consuming an uncertain or failed attempt, provided retries and refusal receipts do not claim execution never occurred.

## Remaining owed before act

1. **Finish message boundaries and failure responses.** `design.md:35–39` and delta lines 45/58 do not say whether an iroh request ends at FIN, a length prefix, or a decoded CBOR object; whether a stream carries one exchange; or how the receipt is framed. Trailing-byte rejection and the five-second read deadline depend on that choice. Pin the bounded request/response exchange, how hello selects/reaches the destination from the signed target, and what each adapter returns on malformed input, absent context, and transport timeout. A malformed request has no trustworthy receipt obligation, and absent context has no signing key: those failures cannot automatically be outcome-1 signed receipts. Distinguish transport/protocol errors from destination-signed outcomes without adding a new product subsystem. Retain a local HTTP→iroh round-trip test and add truncated/trailing/timeout and no-context error cases.

2. **Specify receipt acceptance against caller expectations.** The delta's “A receipt cannot be moved to another request” scenario (lines 60–63) says verification against the destination key fails when an existing receipt is presented for another obligation. Its signature remains valid over its original bytes. Define receipt verification to take the expected destination key, expected obligation, and expected operation, and reject mismatches as well as bad signatures; do not obtain the trusted signer solely from the response. State the outer receipt's first CBOR item's type explicitly (embedded array versus a byte string containing the canonical array), and pin rejection of unknown outcome codes and non-canonical/trailing receipt bytes. Keep outcome 1 explicitly non-evidence that effects never occurred. Require canonical/signature vectors and a substitution test using an unchanged, correctly signed receipt for a different expected obligation or operation.
