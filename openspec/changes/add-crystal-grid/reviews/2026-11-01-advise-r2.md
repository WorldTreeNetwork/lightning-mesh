## Blind independent take

I wrote this before opening design.md, steer.md, tasks.md, or the r1 review. The inputs
were the proposal, the delta, the living spec, `admin/src-tauri/src/canvas.rs`, and the
`SourceState` it embeds from `stdout.rs`.

1. Pin: the well id is the window label that Tauri injects. It is not an IPC argument.
   Today `CanvasState.source` is one app-global `Running`, with one generation counter and
   one `open` flag. The delta pins this ("SHALL NOT be an IPC argument"). Good.
2. Pin: the per-well child. If a fill in A cancels B, the result is silent. The delta
   now has the A/B fill scenario and the close-reaps-only-A scenario. Good.
3. Pin: open mints a label and does not focus the existing well. The cap is 4 and a fifth
   open is visibly refused. Both are pinned.
4. Pin: a minted label is not reused within a session. `on_destroyed` for an old
   `canvas-N` must not deactivate a new well with the same label. "Mint a new label"
   covers this if it is read as unique. A monotonic counter is the obvious implementation.
5. Pin: the cap check and the insert are one critical section. Two concurrent
   `open_canvas` calls must not both pass at count 3. This is implementation, not contract.
6. Refuse: a saved layout, a new source, a 3d engine, and an app-global child. All four
   are refused.
7. Watch: `close_canvas(id)` still takes an id from IPC. Any `canvas-*` page could close a
   sibling. Reaping still keys on the destroyed label through `on_destroyed`, so isolation
   holds. This is not owed.
8. Watch: the placement rule has no number for "one cell step", and it does not say what
   "most recently opened" means once that well is closed. The rule is relative and
   testable, so this is not owed.
9. Tradeoff: N always-on-top vibrancy windows reuse the chrome and gesture contract
   unchanged. The cost is N webviews and no shared frame. That is cheaper than one
   container window with a new layout surface, and it is the right first landing.
10. The RENAMED "Canvas count" body matches its title, and the default source stays
    `ifconfig`.

## Comparison and steelman

Design, steer, and tasks agree with the delta. The send-back section in design.md restates
the same label, cap, and placement pins as the requirement. All r1 owed items (R1–R5) appear
as requirement text or scenarios. I checked each one against the spec, not against the boxes
in tasks.md:

- R1: two isolation scenarios, plus "well id … SHALL NOT be an IPC argument".
- R2: mint a new label, a maximum of four, and the "Fifth well is refused" scenario.
- R3: the placement rule, plus "SHALL NOT snap the well back onto a cell".
- R4: the "One well fails and the other stays" scenario.
- R5: the RENAMED requirement "Canvas count", with the base hash recorded.

Steelman against my take: item 4 (no label reuse) could be read as owed. A literal reading of
"mint a new `canvas-*` label" already forbids handing out a label that is in use. Reusing a
destroyed label after its `on_destroyed` has run is harmless. The race in item 4 is an
ordering bug that an implementer finds by using a counter, so the contract does not need to
name it. Item 5 is the same kind of issue. I note both as guidance for the build tasks rather
than as debt.

The remaining structural change is that `SourceState` moves from app-global to per-label, and
`fill_canvas_source` takes `tauri::Window` and reads `label()`. That change is implementation
the contract now forces, and the scenarios would catch a naive shared child.

## Implementation notes (not owed)

- Mint labels from a monotonic session counter. Never reuse a label.
- Do the count check, the label mint, and the state insert under one lock.
- Have `fill_canvas_source` take the caller's `Window` and key a `HashMap<label, Running>`.
  Have `on_destroyed` reap only that entry.
- Update `CANVAS_ID` users and the `one_canvas_reuses_id` test. `LIGHTNING_ADMIN_OPEN_CANVAS`
  should still open one well.
- Show the refusal for a fifth well on the surface that asked for it (today that is the main
  window through `open.ts`).
