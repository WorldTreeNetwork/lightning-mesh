## Independent blind take

The following ten lines were persisted in this file before opening `design.md` or `tasks.md`, using the proposal, living spec, cited code, and spike finding.

1. Pin the usable local house router `/128` as the mesh Iroh bind and the peer's actual house router `/128` as its connection lookup key.
2. Refuse to treat `bind_addr(/128)` alone as IPv6-only: the spike explicitly observes the retained IPv4 wildcard socket and advertisements.
3. Require the no-house, tentative, DAD-failed, bind-failure, and house-change paths to withhold or retire transport rather than silently restore wildcard or `10.254` binding.
4. Remove `10.254` assignment and its collision healer together; ensure overlay setup and background reconciliation cannot put either back.
5. Pin an explicit association between an authenticated open peer, its house `/128`, and its Babel neighbor link-local; never infer a foreign peer's house from the local house.
6. Require a bootstrap path for Babel multicast and unicast control traffic before any destination host route exists; `fe80` remains a scoped protocol address, not a reversible IPv4 key.
7. Resolve both IPv4 FIB next hops and IPv6 host-route next hops through the same neighbor-to-peer association, preserving IPv4 payload bytes and dropping unresolved destinations.
8. Withdraw stale route and peer associations on route withdrawal, disconnect, and address change; ambiguous or colliding keys must not overwrite another peer silently.
9. Preserve house `/128` usability, recorded-address cleanup, host-only Babel admission, and gateway-default invariants while explicitly reconciling superseded transport claims in the living spec.
10. Accept the tradeoff of losing transport when no usable house address exists, provided the contract makes recovery and underlay-versus-overlay routing explicit and does not claim the spike proves them.

## Comparison and steelman

The delta answers the core direction well: no `10.254` assignment on the named interfaces, no pt9 healing, no IPv4 wildcard bind, one `/128` connection key for both packet families, withdrawal on the next poll, and drops for unresolved destinations. It preserves the detailed house address ownership and admitted-prefix rules. The design also explicitly accepts that the unchanged fleet column will stop reaching converted nodes; rewriting inventory is not an owed action here.

The strongest argument against my blind concerns is that a small contract should state behavior and leave parsing, maps, and retry machinery to act. I agree: this review does not require a particular map implementation, a new collision allocator, or another successful ULA dial spike. However, “Babel's neighbor for the route carries the peer `/128`” (`design.md:7`) assumes the central data source exists. Neither the cited implementation nor the spike supplies that relationship. Leaving its provenance and bootstrap to act delegates an architectural choice, rather than a routine implementation detail.

## Owed before fresh advise

### R1 — Specify the neighbor-to-connection association

`ConnManager::register` currently receives an authenticated endpoint id and derives its IPv4 index locally (`mjolnir-meshd.rs:8277`). `parse_ula_host_routes` reads only destination and `via`, then reverses a link-local into IPv4 (`tun/ula_host.rs:10`). The IPv4 mirror likewise accepts only an IPv4 gateway (`mjolnir-meshd.rs:8440`). None of those inputs contains a neighbor's house guild or house router `/128`.

Name the actual Babel observation/interface and fields that identify the selected neighbor, and the source that associates that neighbor's link-local and house `/128` with the authenticated open Iroh peer. Include interface scope, how a foreign-house neighbor is represented, and behavior for missing, ambiguous, changed, and disconnected associations. A destination host's `/128` cannot stand in for its transit next hop's `/128`. The directory's existing neighbor reference is computed using the local house (`identity-derived-ula/spec.md:252`), so it is not evidence of a foreign neighbor's actual transport address.

Acceptance evidence should include one route whose destination differs from the next-hop router, an admitted foreign-house next hop, an IPv4 destination using that same peer with unchanged payload bytes, and association withdrawal/replacement. A fixture of the proposed Babel observation is enough for contract review; do not invent an API from the sentence in the design.

### R2 — Explain cold bootstrap and keep the transport path independent of its tunnel

The existing link-local is derived from the old 16-bit IPv4 host (`tun/iface.rs:26`), and Babel link-local unicast is dispatched through that reverse derivation (`mjolnir-meshd.rs:8365`). Multicast already floods established connections (`mjolnir-meshd.rs:8418`). Removing the reverse mapping therefore also needs a rule for selecting the connection that carries Babel's unicast control traffic before destination routes are learned. State whether the link-local derivation is retained as a protocol address or replaced, and how ambiguous neighbors are handled after pt9 is disabled; this does not reopen the `/128` key decision.

Also state how the first remote `/128` becomes reachable for Iroh and which route/interface carries its UDP packets. The spike supplies host routes manually and uses `nodad`; it does not demonstrate daemon cold start or underlay Babel setup. The current router explicitly drops overlay traffic to `10.254/16` to prevent Iroh from recursively using its own overlay (`mjolnir-meshd.rs:8345`). The new key lives in the same address family and space that the overlay now forwards. Explain the equivalent separation when a peer host route appears on `mjolnir0`, without blanket-dropping legitimate house host traffic.

Add a cold-start verification journey with no pre-existing Iroh connection or overlay host routes, Babel control exchange, then IPv4 and IPv6 forwarding; include a peer `/128` route change that cannot turn the outer transport into Iroh-over-itself. This may be established in an isolated fixture and requires no fleet deployment or mesh errand.

### R3 — Specify endpoint startup, invalidation, and recovery

“Usable `/128`” and “no `0.0.0.0`” are necessary constraints, but they do not state what the daemon does while no usable house address exists. Today endpoint creation is a one-time operation (`mjolnir-meshd.rs:467`), house reconciliation runs separately (`:7673`), and bind failure explicitly falls back to all interfaces (`:8870`). House reconciliation deletes/replaces addresses without rebuilding an endpoint (`:7680`). The copied directory-publication scenarios cover address state, not transport lifetime.

Specify the startup ordering and the wait/retry or restart behavior for absent/malformed guild, tentative/DAD-failed address, bind failure, interface recreation, and guild replacement/removal. Define when the old endpoint, advertisements, and connection keys cease to be usable, and how a newly usable address restores transport. Identify the supported Iroh 1.0.0 builder configuration that removes the default IPv4 socket; the existing spike explicitly proves that adding an IPv6 `bind_addr` alone does not do so. Define how this contract applies to mesh overlay/LAN/internet paths and explicit `--bind`, since the current startup selects different binds for those modes.

Add focused checks of bound sockets and advertised addresses, cold address assignment, and a running house-address change or loss/recovery. The existing successful `/128` dial remains valid evidence for its narrow claim.

## Contract observations

The delta replaces the full living requirement and retains its address cleanup, host filters, retry, and gateway-default provisions. It removes the old sentence “IPv4 Babel next hops SHALL stay link-local” without an explicit replacement; R1 should make the intended next-hop representation explicit. The adjacent operator-reference requirement still labels `10.254` as the transport pin. The design acknowledges the stale fleet address deliberately; record that as a transitional compatibility limitation when reconciling the remaining directory/Admin wording, without expanding this node into an inventory rewrite.
