## Blind take (written before design.md / tasks.md / r1 were opened)

Sources: proposal Why, identity-peering-requirements "Gating open
backhaul", island-formation decisions 4/6, `crdt/gossip.rs` (enum and
doc comments), `crdt/leased_name.rs`, `mjolnir-meshd.rs` ingest ~L1395
and `apply_subnet_message` ~L1926, `babel/config.rs`,
`setup-wireless.sh` L31/L131, `fleet-secrets/wireless.env`, the spec
delta.

1. Pin: a grant must be a CRDT-carried, subject-signed record whose check at merge is local and clock-free (leased_name's `cross_owner_winner` shape), or "merge verifies the grant" is unimplementable in the pure-merge gossip model.
2. Pin: the grant lane is itself a CRDT lane. Who writes the first grant? The root of authority must be named or the gate is circular.
3. Pin: a quarantined joiner needs an address to run the iroh handshake, but backhaul `/32` claims are gated. The quarantine lane must ride link-local or an ungated ephemeral address, not a claimed `10.254`.
4. Pin: the per-peer tunnel interfaces (`mj-peer-* type tunnel` over iroh) already are per-identity authenticated babel sessions; the unauthenticated surface is the `type wireless` br-mesh interface. babeld 1.13 RFC 8967 keys are per interface, not per neighbor, so "per-identity babel" implies a mechanism the design should commit to.
5. Refuse: hop allow-list or fleet babeld HMAC as a gate.
6. Refuse: reading leased_name as a working precedent for merge-time verification. At HEAD meshd trusts the ingesting node's ceremony-time check and does not re-verify (`mjolnir-meshd.rs` ~L1395, ~L2957). The pattern exists on the wire, not in merge.
7. Tradeoff: adding a signature field to every production record is a postcard wire break on every lane (LeasedName's own note) and breaks loading persisted books on upgrade. Either new signed variants appended to the enum with old ones frozen (the D-004 `ServicePublishV2` precedent) or a topic bump. Design should own this before act discovers it.
8. N3 is conditional: HWMP poisoning by a quarantined station is DoS-only only if trusted babel is never spoken unauthenticated on br-mesh.
9. Overlay SSH: on a flat L2 a quarantined station reaches `10.254` without babel and can spoof source. The load-bearing gate is dropbear key auth plus rate limit, not a source rule.
10. `MESH_KEY` is empty at HEAD (`fleet-secrets/wireless.env` L2; `setup-wireless.sh` renders `encryption=none`). A SHALL that says otherwise would be archived false.

### Send-back reasons

**S4. Negative mutations escape the S1 invariant.**
The amended requirement signs production *records*. The wire also
carries unsigned negative messages: `SubnetClaimRelease { cidr, hlc }`,
`LeaseRelease { mac, hlc }`, `ServiceUnpublishV2 { name, owner_node_id, hlc }`.
`apply_subnet_message` (meshd ~L1953) removes any claim whose
`claimed_at` is at or before the release HLC, with no owner check even
against the self-declared id. So after S1 lands as written, an enrolled
member still evicts another identity's `/24` or backhaul `/32` claim by
gossiping a release with a fresh HLC; the victim node then retracts its
gateway and re-claims (the `pt9` exit-and-respawn path). The anchor
invariant, "merge verifies subject signature and grant", is stated for
records and silently not for releases, tombstones, and unpublishes.
A second, smaller gap: for keyed messages the lane key (`cidr`, `name`,
`mac`) sits outside the entry. If "canonical record" means the entry
only, an enrolled relay can re-key a genuinely signed entry under a
different cidr and the signature still verifies.
Owed: one sentence that every production mutation, including release,
tombstone, and unpublish, is subject-signed over canonical bytes that
include the lane key and the HLC; a scenario "enrolled member cannot
release or tombstone another identity's claim".

**S5. The enrolled-unowned-prefix scenario is not transit-safe as written.**
"Announced prefixes SHALL be prefixes the announcer is authorized to
claim" and the scenario "E announces `10.42.99.0/24` ... other nodes do
not install" read as a per-neighbor binding. babel is distance-vector:
a jump node legitimately re-announces every prefix behind it over the
`mj-peer-*` tunnels, so a per-neighbor binding breaks cross-site
routing outright. The only binding babel can express is on the update's
router-id (babeld `in id <router-id> ip <prefix>` filters), and an
*enrolled* neighbor can forge another member's router-id on a
fabricated update. So the scenario holds when E originates as itself,
and does not hold when E lies about origin. The delta must pick: bind
on router-id origin and name enrolled-insider origin forgery as
residual handled by revocation (R5), or owe route-origin proof. Either
is fine; the current text promises the second while act can only
deliver the first.
Owed: rewrite the binding as router-id origin; scope the scenario to
"E originates `10.42.99.0/24` under its own id"; add a sentence in
design.md naming enrolled-insider origin forgery as accepted residual
(or an owed box for origin proof).

### Notes (not blocking)

- **N6 wire migration.** Take 7. Signed records should land as new enum variants with the old ones frozen (the `ServiceUpdate` → `ServicePublishV2` precedent), and the persisted claim/addr books need a load path that does not fall back to empty on the schema change, or `pt9` backhaul claims renumber on upgrade. One design.md line under a "Migration" pin would stop act from doing it in place.
- **N7 quarantine-lane addressing.** Take 3. The handshake needs an address the joiner can use before any claim merges. Say link-local or ephemeral; do not let act pick "self-assigned `10.254` that nobody merges", which collides silently.
- **N8 SSH wording.** Take 9. "unauthorized key or source" is fine if "source" is read as defense in depth; key auth is the gate on a flat L2 where source is spoofable.
- **N9 join doc.** The HEAD paragraph already says "no membership gate yet"; the owed box is to add "until the three gates land" and name them, nothing more.
