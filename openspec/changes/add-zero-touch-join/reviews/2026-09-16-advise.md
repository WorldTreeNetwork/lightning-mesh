## Blind take (written before design.md / tasks.md / spec delta were opened)

Sources: proposal Why, identity-peering-requirements R1–R6 + "Gating open backhaul", island-formation decisions 4/6/7, join doc 03, meshd peer-set resolution (`mjolnir-meshd.rs` ~L914–930, ~L1101–1165), `bootstrap.rs`, `crdt/gossip.rs`, `babel/config.rs`, `setup-wireless.sh`.

1. **Pin: origin, not hop.** iroh authenticates the *hop*, not the *author*. Gossip messages carry self-declared `node_id`/`owner_node_id` strings, the topic id is a public constant (`blake3("mjolnir/mesh/crdt/v0")`), and the CRDT applies with no signature check (`gossip.rs` L134, `merge.rs` L170). So "identity-authorized CRDT writes" (fyby.3) must mean per-message Ed25519 signatures by the subject (as `leased_name` already does), not a sender allow-list at the gossip router. An allow-list alone lets any enrolled member forge claims/addr-book entries for any other id.
2. **Pin: 661 must be per-identity, not one fleet HMAC key.** babeld's RFC 8967 MAC is a per-interface shared key. Shipping that as "authenticated babel" recreates the SAE insider-complete flaw R1 rejects. Per-identity babel means neighbor admission bound to a node-id handshake (firewall/ebtables gate on br-mesh keyed by MAC↔node_id proof, or per-neighbor derived keys), and the spec must say which.
3. **Pin: quarantine is a firewall posture on br-mesh, not a meshd flag.** Overlay SSH is dropbear on `10.254.x` reachable by anyone who assigns themselves a 10.254 address on the bridge. Quarantine must drop input from non-admitted source MACs on br-mesh except the enrollment lane (link-local handshake + iroh port for the challenge), and must cover babel multicast, ARP, and dropbear alike.
4. **Pin: `mesh_fwding=1` means an associated stranger is an L2 forwarder (HWMP) for the whole segment.** Quarantine at L3 does not stop a quarantined station from relaying or black-holing legit nodes' frames. Name this as accepted DoS-only exposure (iroh is E2E), or gate on `mesh_fwding=0` for open backhaul.
5. **Pin: the live fleet backhaul is open today** (`MESH_KEY` empty ⇒ open; join doc says "no membership gate yet"). Requirements say backhaul stays closed until the two gates hold. The change must state the interim honestly: nothing in it may make the open fleet *more* exposed before quarantine lands. Concretely: capability beacon (a locator that advertises "mjolnir vN fleet X") ships no earlier than quarantine.
6. **Pin: grant provenance.** "An existing member accepts the beacon offer" needs: who may grant (any member? admin key?), the grant is a signed CRDT record naming grantor+grantee+capabilities, and it is tombstone-able so R5 revocation can land later without a schema break.
7. **Pin: `list peer` stays the only *configured* bootstrap; `bootstrap.rs` already unions addr-book and claim owners into dial candidates (f8b).** After enrollment a new id enters those books via gossip. That is fine and is the actual zero-touch path. The spec must say the RF neighbor table is never a source for any of roster, addr-book, or claim-owner sets; only authenticated gossip and inventory are.
8. **Refuse:** any wording that lets association, a heard beacon, or a successful iroh handshake alone move an id from quarantined to member. Refuse a single fleet-wide babel key as satisfying 661. Refuse "iroh authenticates the CRDT plane" as a premise for skipping message signatures.
9. **Tradeoff I would take:** plug-and-wait yields *discovered and waiting*, not *joined*. A factory node in RF range stays a lone `10.42` island until a human enrols it (QR or offer accept). Slower than the operator's wish, but it is the only reading consistent with "discovery, not trust". The cost is a visible pending state (hello/LED) so the wait is legible.
10. **Order I would insist on:** quarantine firewall (fyby.2) → message signatures + identity-scoped FWW (fyby.3) → babel neighbor admission (661) → beacon + enrollment offer. Beacon last, because it is the only piece that increases the attack surface of the still-open fleet.

## After opening design.md, tasks.md, the spec delta, steer.md, and beads

### Where the change already answers the take

- **Association / beacon / handshake are never sufficient** (take 8): the delta says so three separate ways (Discoverable is not trusted; Replay is not a ticket; Grant lifts quarantine). Consistent with steer fork 1.
- **Grant provenance** (take 6): answered by `docs/network-coordination/membership-enrollment.md`, which the design cites. Endorsements are signed `/members/{subject}` records with epoch-dominant revocation and per-device threshold policy. The delta binds the beacon offer to "the same endorsement rules as QR". Good.
- **Overlay SSH under quarantine** (take 3): a SHALL exists. Mechanism is unspecified, which is acceptable for a spec, but see note N2.
- **`list peer` never fed from RF** (take 7): stated in delta, design, steer, and the `m4a` bead. `bootstrap.rs` unions addr-book and claim owners, which is fine once fyby.3 authorizes those lanes.
- **Tradeoff** (take 9): the change takes it. Plug-and-wait yields found-and-waiting, with a visible pending state in hello/LED/log.
- **Ordering** (takes 5 and 10): I wanted beacon last. The design puts e5u second, before quarantine. Steelman: the mesh_id is already in 802.11s beacons, `/api/directory` on the open client SSID already serves node ids of self and neighbors, and the nonce-bound handshake that e5u builds is the thing the quarantine lane rides on. My exposure argument is weaker than I wrote it. Downgraded to note N1.

### Where the take is not answered (send-back reasons)

**S1. Gate 2 as written can be satisfied by a hop allow-list, which does not authorize writes.**
iroh authenticates the *delivering neighbor*, not the *author*. Gossip is epidemic. Every production lane today carries a self-declared subject string (`owner_node_id`, `node_id`, `stamper`) and merge verifies no signature (`crdt/gossip.rs` L134, `crdt/merge.rs` L170, `crdt/coordinate.rs` L23). The delta's "accept only writers whose identity holds a grant" and the scenario "node S has no claim-write grant … members do not install" are both satisfied by checking the grant of the *hop*. That leaves the real attack open: an enrolled member relays a claim whose subject is another node, and it merges. The design's "iroh authenticates the gossip/tunnel ALPN" is true at the hop and is exactly the premise that hides this. `leased_name` already does it right (subject signs a canonical message; anyone verifies). The delta must say that, generally.
Owed: production writes carry an Ed25519 signature by the subject over the canonical record; merge verifies signature *and* grant; a scenario where an enrolled member cannot forge another id's record; a named carve-out for the coordinate lane (stamper ≠ subject, stamper signs and stamper must hold the stamp grant).

**S2. Gate 1 as written can be satisfied by one fleet-wide babeld HMAC key.**
"Authenticated neighbor session with freshness" is exactly what babeld's RFC 8967 MAC provides, and it is a per-interface shared key. That is the SAE insider-complete shape R1 rejects: one leak admits anyone, and R5 revocation would mean rekeying every node. The delta also drops the original content of `661` (route-origin validation: only the id whose claim holds a `/24` may announce it, default only from a gateway). Sol's caution added session/freshness *to* origin, not instead of it. As written, an enrolled neighbor may still announce a victim's `/24` or `0.0.0.0/0`.
Owed: a SHALL that neighbor admission or session keys are per node identity, such that revoking one identity requires no rekey of others; a SHALL binding announced prefixes to the announcer's authorized claims, with the default route requiring a gateway grant; a scenario for an *enrolled* neighbor announcing a prefix it does not own.

**S3. A SHALL nobody owes.**
"Until then, trusted-fleet operation SHALL use inventory bootstrap and/or a shared mesh key" is false of the live fleet (`MESH_KEY` empty means open, per `setup-wireless.sh` L31 and the join doc), and the proposal puts changing `MESH_KEY` out of scope. A folder would archive a SHALL that HEAD violates. Either the fleet key becomes an owed box, or the sentence becomes a documentation SHALL (the join doc states there is no gate), which tasks.md already owes.
Owed: rewrite that sentence one way or the other.

### Notes (not blocking)

- **N1 ordering.** Keep e5u second if the beacon IE ships behind a flag or only on nodes that also enforce fyby.2. Node ids are already public via `/api/directory`, so this is hygiene, not a gate.
- **N2 quarantine mechanism.** The cleanest realization of fyby.2 is a br-mesh input policy keyed on admitted station MACs, with the enrollment lane the only exception. It covers babel multicast, ARP, and dropbear in one place. Note that MAC is a locator only; a quarantined station on an open backhaul can spoof an admitted MAC, which is why S2's cryptographic session is the actual gate and MAC filtering is defense in depth.
- **N3 HWMP.** `mesh_fwding=1` (`setup-wireless.sh` L131) makes any associated station an L2 forwarder for the segment. A quarantined stranger can relay or black-hole legit nodes' frames. That is DoS only, since iroh is end to end and S2 authenticates babel, but it belongs by name in the design's residual-RF-risk list.
- **N4 grant is per node.** Under `membership-enrollment.md`, acceptance is each device's local policy (threshold K, allow, block). "An authorized member records a grant, then B may participate" is true per accepting node, not mesh-wide. Worth one sentence so the UX expectation is honest.
- **N5 today-shaped scenario.** "Today-shaped fleet stays honest" is false at HEAD: babeld on `br-mesh` is `type wireless` and multicast-discovers every station (`babel/config.rs` L114). Fine for a delta, but the folder should not read it as evidence of current behavior.
