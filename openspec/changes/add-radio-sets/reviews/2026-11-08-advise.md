## Blind take

Written before opening design.md, tasks.md, or the proposed deltas; based only on the packet's Why, the four cited living specs, cited code, and LEARNINGS entries.

1. Pin one authoritative radioset for phy roles, with wired profiles referring to it rather than retaining a competing assignment map.
2. Pin deterministic per-model physical-radio resolution; refuse missing, ambiguous, or duplicate matches instead of first/last-band-wins selection.
3. Pin exactly one active function per phy and an explicit safe outcome for every extra or unassigned radio, including stale wifi-iface sections.
4. Pin the OpenWrt One default to 5 GHz mesh and 2.4 GHz client AP with Ethernet WAN; station legality must not change that selection.
5. Keep client SSID/security in mjolnir.radio and make radioset projection use those settings without introducing a second source of truth.
6. Require repeated projection to preserve an assigned station and its candidate-bound secret; refuse unowned stations before any mutation.
7. Keep station credential authorization, LAN isolation, default-route evidence, and the missing live-probe gate owned by wifi-internet-uplink.
8. Require radioset selection and any composed wired changes to share revision checks, complete rollback inputs, and one durable transaction.
9. Preserve wired-core separation, cable-loss guarantees, gateway exports, and mesh reachability checks when moving radio decisions out of profiles.
10. Tradeoff: exclusive phy roles simplify validation but forgo concurrent AP/STA or mesh/AP use; state how existing and disabled co-located sections migrate.

## Comparison and steelman

The capability split is right. The design answers the central concerns in blind points 1, 4, 7, and 8: profiles reference a radioset, the One keeps its existing split, upstream probes remain deferred, and combined changes use one transaction. Exclusive functions plus disabling omitted mapped phys address the intended safety tradeoff. Keeping the One map unqualified is honest; this review does not require hardware qualification or live station work.

The strongest reading is that sets will be immutable image data, the existing transaction engine supplies recovery, and generic apply only preserves an already-authorized station. Those choices would keep this small. However, the documents do not yet pin those choices at the boundaries below. These are contract corrections before act, not requests to build the deferred capabilities.

## Required corrections

### R1 — Preserve the peer-isolation acknowledgement (high)

The full replacement of “Wired-core keeps the three domains apart” drops the living requirement to refuse `isolate` without explicit acknowledgement when a current mesh peer has no other path. Compare `openspec/specs/node-connection-profiles/spec.md:40` with this change's `specs/node-connection-profiles/spec.md:41`. The current decider enforces it through `wireless_only_peers` and `acknowledge_stranded_peers` (`crates/mjolnir-apply/src/node_profile.rs:621`). Folding the replacement would silently remove that safeguard. Management and mesh health do not substitute for the owner's acknowledgement about stranded peers.

Restore that clause in the composed profile/radioset validation, and add a scenario for switching to an isolating wired profile with wireless-only peers and no acknowledgement. The split may relocate the check; it must not erase it.

### R2 — Specify the canonical radioset definition and replay rules (high)

`design.md:5` records only `mjolnir.radioset.id`; `design.md:11` specifies storage for hardware maps, not the named function assignments. The default id also has two opposite band assignments selected by `BACKHAUL_BAND` (`specs/radio-sets/spec.md:17`). Neither the definition store nor the persisted variant is specified. An id alone cannot reconstruct which split was committed after the environment disappears, nor explain what happens when image data changes beneath that id.

Pin where named definitions live, how an id resolves to a model-specific assignment, and what committed data distinguishes the 2g variant. Define unknown-id refusal, profile-reference precedence, and how definition/selection changes participate in revision checks and rollback. Immutable versioned definitions or committed resolved assignments are both defensible; choose a contract. Add a restart/re-apply scenario after selecting the 2g variant, without the selecting environment, plus failure restoration of that exact selection. Reconcile first adoption of the id with the promised default no-op: current profile code treats an absent id as the default (`node_profile.rs:1169`).

### R3 — Define physical identity resolution and mismatch behavior (high)

The model example uses `radio0`/`radio1` as phy ids, while the default scenario uses `phy0`/`phy1`; the map also carries `path` and `band` without defining which identifies hardware (`design.md:17`, `specs/radio-sets/spec.md:20`). With two 5 GHz phys, the default still says “5 GHz phy” without specifying which one. Replacing the last-wins loop requires an unambiguous model-to-inventory match, not just a JSON parser.

Define the identity namespace and resolution rule, with refusal before mutation for wrong-model, missing required hardware, duplicate/ambiguous matches, and assignments to unknown ids. State how unqualified defaults are admitted and how a detected phy absent from the map is handled; keep that distinct from a mapped-but-omitted phy. An explicit unmanaged-device boundary is acceptable for the existing dongle owner. Add fixtures for reordered UCI names, two same-band phys, and a map/inventory mismatch. This closes blind points 2 and 3 without requesting third-radio qualification.

### R4 — Pin the shell projector and station-preservation boundary (high)

`design.md:43` refuses live adapter submission, but `tasks.md:6` changes the shell projector and the station SHALL explicitly uses `RUN_WIRELESS=1`. That path currently invokes `/root/setup-wireless.sh` (`deploy/openwrt/files/usr/sbin/mjolnir-apply:554`), whose body directly commits UCI and restarts services (`deploy/openwrt/setup-wireless.sh:245`). The Rust adapter gate does not by itself constrain this path. Also, `tasks.md:16` hands generic station preservation to 9d3o while the new SHALL already requires it here.

Specify which entry points may render, preserve an unchanged station, or refuse changes until live probes exist; no alternate shell path may bypass the transaction/health gate for a radioset change. Reconcile the preservation SHALL with the 9d3o handoff by naming exactly what this change delivers. A role label must not authorize a new association or adopt an arbitrary existing STA: retain unowned-station refusal (`node_profile.rs:489`), candidate binding, and the `ProvesUpstream` submission boundary (`uplink.rs:261`). Define the handling of stale enabled interfaces and the existing disabled `clientap2g` section so exclusive roles and the no-op fixture agree.

Add focused acceptance coverage for unchanged assigned-station re-apply, unowned STA refusal before mutation, live-path refusal of unsupported changes, and composed profile/radioset rollback. Preserve station network/secret ownership; upstream commit and live evidence remain with 21rw.
