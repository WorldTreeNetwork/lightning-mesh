Reviewed the ACTIVE BUILD proposal, design, tasks, and identity-derived-ula delta against the three cited living specs and the cited implementation. This is a contract review before implementation. The independent ten-line [blind take](2026-11-01-blind-take.md) was persisted before opening design.md or tasks.md.

The host-route approach is sound: both renders gain only `in`/`out` `/48 eq 128` exceptions before the ULA denies; local redistribution remains the usable house `/128`; foreign addresses are not assigned. The gateway export, IPv4 next hops, Iroh bind, and existing overlay host-route selector remain outside this change. Three boundaries need to be made executable before act.

## R1 — Own-house exclusion must survive an unusable router address

`design.md:11,30` supplies `read_admitted_prefixes()` beside `known_house_router` and excludes the own-house prefix because “the house allow already covers it.” That explanation does not hold when the configured house address is tentative, DAD-failed, absent, or on the wrong interface. `known_house_router` (`mjolnir-meshd.rs:8574`) deliberately returns `None` in these states. The delta nevertheless allows counted foreign prefixes without a usable local house and still requires this node's own prefix not to count.

Pin how the projection reader/render boundary obtains the configured house prefix independently of address usability. For example, with guild A configured, no usable A `/128`, and projection entries A and B, both renders must exclude A and may allow B; neither may redistribute a local house host. Specify the missing/malformed-guild case and a guild-change transition too. The implementation must not infer “foreign” merely from `house_router == None`. Add these cases to the contract and verification tasks.

## R2 — Identify the excluded prefix and the trusted-input boundary precisely

`design.md:29` and the delta name a “compiled stock OpenWrt prefix,” but the cited implementation distinguishes two things. `tun/link.rs:44` derives the compiled legacy mesh prefix through `ula_prefix()`; its fixture is `fd53:6213:4797::/48`. `babel/config.rs:426–427` checks that prefix and the separate stock negative `fd12:3456:789a::/48`. The design never identifies which value/source its mandatory skip means. Its “any other well-formed /48” rule would accept the stock negative if that line were supplied and only the compiled legacy prefix were excluded.

Name the exact excluded value/source, distinguish legacy mesh ULA from stock OpenWrt ULA, and state which exclusions the caller guarantees versus which the reader enforces. State whether a supplied `fd12:3456:789a::/48` must be rejected or is forbidden input from the trusted publisher. Do not promise rejection of arbitrary stock prefixes from a prefix-only file without a source for identifying them. Also pin the permitted address range: the current grammar admits any IPv6 network `/48`, whereas house derivation produces `fd00::/8`. Align design, delta, and negative fixtures, including direct renderer input, on these decisions. No guild-log or signature verification is requested.

## R3 — Removal must reach running Babel after a failed restart

Reading the projection on each pass does not guarantee removal from the running daemon. In the overlay reconciler (`mjolnir-meshd.rs:8629–8649`), a successful config write advances `last_rendered` even when service start/restart fails. The next identical render skips the entire block. In the other reconciler (`:8021–8038`), a failed restart after a changed write is followed by `changed == false` on the next pass, so the restart is not retried. This is existing behavior, but using it for admitted-prefix removal can leave the previous allow active, or Babel stopped, indefinitely without another input change.

Specify successful application separately from a successful file write and require pending start/restart failures to be retried with bounded pacing in both modes. Add verification for B allowed → B omitted/file missing → config written → restart fails → unchanged next pass retries and successfully applies the deny. Pin unreadable-file behavior as well; it is currently unspecified. This asks for contract/tasks now, not product implementation during advise.

## Comparison and steelman

The design answers blind concerns 1–3 and 7–8 directly. Its independent foreign allows when no local address is usable are a defensible choice: a transient DAD/interface problem need not disable transit for an independently supplied admitted set. I therefore do not require all foreign allows to be gated on local address usability. R1 only preserves the separate own-house exclusion.

The strongest case for the plain projection is deliberate separation of signing from routing. The publisher is explicitly deferred, and stale lines are explicitly retained until removal; that is an acceptable bounded reader feature, not a request to implement Admin publishing here. However, the file is trusted routing-policy input in operation. The future publisher must select pairs for the intended house and replace its projection when that house changes; the router cannot establish that relationship from bare prefix bytes. Document this responsibility rather than claiming the reader verifies admission. This resolves the blind take's house-binding concern without adding cryptography or a competing architecture.

Blind concerns 4–6 and 9–10 remain only partly answered, specifically by R1–R3. Stable ordering/deduplication would also avoid restarts for equivalent projection sets; that is an implementation consideration, not an additional blocker. The existing demux test is an appropriate regression but cannot substitute for removal/restart coverage.

No product code, living spec, proposal/design, or disposition banner was changed. No runtime tests were run for this documentation review. Owed boxes are appended to tasks.md; the author should reconcile the contract and return it for fresh advise before act.
