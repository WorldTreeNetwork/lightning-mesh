## Blind take (written before opening design.md / tasks.md)

Inputs: proposal Why, `openspec/specs/link-local-mgmt/spec.md`,
`ipv6-addressing-decision.md`, `ipv6-parallel-plane.md`, `tun/link.rs`
(`backhaul_addr`, `backhaul_addr_salted`, `BACKHAUL_PREFIX_LEN`),
`tun/iface.rs` (`overlay_link_local`), `mjolnir-meshd.rs` (`DirectoryNode`,
`reconcile_backhaul_addr`), `babel/config.rs` (both renders' deny lines).

1. PIN prefix shape: RFC 4193 `fd` + 40-bit global id + 16-bit subnet +
   64-bit IID. Global id must be mesh-derived or a documented constant, NOT
   node-derived; IID = `blake3(node_id)[0..8]`. Otherwise no two nodes share
   a `/64` and nothing is on-link until `v6.4`.
2. PIN on-link: the ULA goes on `br-mesh` as a `/64` so same-island
   neighbours reach it with zero routing. Cross-site over `mjolnir0` is out
   of scope (`v6.4`).
3. PIN no babel export: `redistribute local deny` + `redistribute deny` swallow
   v6 locals/connected; add a test that no `fd` route is exported and v6
   import is denied.
4. PIN reconcile: netifd wifi reload flushes `br-mesh`; `reconcile_backhaul_addr`
   collects only `IpAddr::V4`. The ULA needs the same 3 s re-add and must not
   spin on a DAD-failed address.
5. PIN directory: one new `DirectoryNode` field, `skip_serializing_if` None;
   `backhaul_addr` stays the `radio.json` join key. Never `mjolnir0`'s fe80.
6. PIN stability across `pt9`: `10.254` may re-derive; the ULA never does.
7. REFUSE any RA of this `/64` on `br-mesh` (odhcpd must not treat `br-mesh`
   as `ra=server`); RA is `v6.3` and `br-lan` only. Routers must not SLAAC
   each other.
8. REFUSE AAAA, `.mesh`, `mjolnir0` addressing, iroh candidate changes, and any
   CRDT claim for the ULA. Parallel plane, not a swap.
9. REFUSE touching the stock OpenWrt `ula_prefix` `/48` on `br-lan`.
10. TRADEOFF: shared `/64` (on-link now, island-scoped, cross-site waits for
    `v6.4`) vs per-node `/128` from a per-node `/48` (routing-clean, dead until
    babel v6). Take the shared `/64`; the LL requirement already lives at
    island scope.

## Compare (after design.md, tasks.md, delta spec)

Steelman: the amended design answers every pin in my take, and every
owed item from the first pass, with more precision than I asked for.

- Take 1 / S1 — design: global id = first 40 bits of
  `blake3(b"mjolnir/mesh/ula/v0")`, exact 20 ASCII bytes named, domain-
  separated from the CRDT topic, golden vector test owed. Subnet id 0. IID =
  first 64 bits of `blake3(node_id)` as opaque bits (RFC 7136), IID 0 clamped.
  Answered, byte-exact.
- Take 2 / S2 — design "Where it lives": `br-mesh` only, `/64`, not
  `mjolnir0` (connected `/64` on the TUN races the on-link route and
  black-holes pre-`v6.4`), not `br-lan`. Delta spec says the same in SHALL
  form. Answered. The `mjolnir0` defect from pass one is gone.
- Take 3 / S4 — design "Babel containment": `in ip fc00::/7 deny` and
  `out ip fc00::/7 deny` in BOTH renders; delta spec scenario "Not exported by
  babel; stock `ula_prefix` stays filtered" inspects both renders. Answered.
  `fc00::/7` also covers the stock random `/48` regardless of what the mesh
  constant hashes to. Good choice over a `/48`-specific deny.
- Take 4 / S3 — design "DAD and reconcile": reconcile loop SHALL re-add the
  ULA; address added `nodad`, with the reason stated (hash, not a SLAAC
  guess; no 1 s tentative hole after every wifi reload). Answered.
- Take 5 — delta spec "Directory publishes it", omitted when unassigned.
  Answered.
- Take 6 / Take 8 — design "Derivation": never coupled to the IPv4 host16,
  `pt9` may move `10.254`, ULA does not move. "What we refuse" lists the
  host16 and the CRDT topic as inputs. Answered.
- Take 9 — "Replacing OpenWrt's random LAN `ula_prefix`" refused. Answered.
- Take 10 — compiled constant `/48` now, `yau` may introduce per-mesh later.
  Same call I would make; the user journey "computable from node id alone"
  is literally true.
- S5 — design "iroh non-candidate": filter explicitly, expose a runtime
  observable, fleet health-gate grep for no `fd` candidate. Delta spec
  scenario "Overlay IPv4 still the underlay" checks status / `/api/node`.
  Answered.

Feasibility, verified against the tree so the implementer does not hit a
wall the design did not foresee:

- `nodad`: `rtnetlink` 0.21 `AddressAddRequest::message_mut()` exposes the
  header; `netlink-packet-route` 0.29 has `AddressFlags::Nodad`
  (`IFA_F_NODAD`). One line, no shell-out.
- Explicit iroh candidate filter: the mesh publishes its own dial candidates
  in `build_self_addr_entry` (`mjolnir-meshd.rs` ~4827) from
  `endpoint.addr().ip_addrs()`. Filtering `fc00::/7` there is our code, not an
  iroh API. The observable already exists: `DirectoryNeighbor.addrs`
  (`~3365`) is the projected `direct_addrs`. S5 is implementable as specified.
- No RA on `br-mesh` (my take 7): `setup-wireless.sh` sets
  `network.mesh.proto='none'` and there is no `dhcp.mesh` section, so odhcpd
  will not RA the `/64`. Holds today by absence, see note below.
- Babel: babeld `in`/`out ip` filters accept IPv6 prefixes; the two golden
  tests in `babel/config.rs` will change and must be re-pinned.

Nothing in my take is unanswered. No design defect found. Accept.

## Notes (body, not verdict)

These are polish for the act pass, not conditions on the accept.

- Tasks box 4 still reads "iroh candidate list still IPv4-only (test or
  comment guard)". S5 supersedes it ("not a comment guard"). Reword box 4 at
  act time so the two boxes do not contradict; the owed S5 box is the one
  that counts.
- Tasks box 1 names `ula_addr(mesh_id, node_id)` while design.md says the
  `/48` is a compiled constant. Keep the parameter: pass the 20 constant
  bytes in from a `pub const` in the lib so Admin and a future app call the
  same pure function. Do not hide the constant inside the bin.
- Write one ADR sentence that `br-mesh` MUST NOT carry a `dhcp.<mesh>`
  section with `ra=server`, so `v6.3` does not casually add one and make
  routers SLAAC each other from this `/64`.
- Write one ADR sentence that cross-site peers' ULAs look on-link on
  `br-mesh` but are unreachable until `v6.4`, so nobody files it as a bug.
- The reconcile loop's `present` collection is `IpAddr::V4`-only; widen it
  (or add a parallel V6 collection) rather than assuming the dump shows the
  ULA. A `dadfailed` flag cannot occur with `nodad`, so the spin concern from
  my take is moot; still, do not re-add on `EEXIST`.
- Delta spec "SHALL NOT add that ULA to iroh's QUIC candidate / bind set":
  iroh binds `[::]`, which implicitly covers it. The enforceable half is
  "candidate set"; keep that phrasing in the folded spec.
- Proposal "User journey" says `ula` / `ula_prefix` fields; delta spec says
  "includes the ULA". Pick the field names at act time and keep them
  additive with `skip_serializing_if`, like `link_local_*`.
