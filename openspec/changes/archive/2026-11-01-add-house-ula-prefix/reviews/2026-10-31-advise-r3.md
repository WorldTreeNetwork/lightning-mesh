## Comparison against R2a–R2c

**R2a is resolved.** The design identifies `/var/lib/mjolnir/house-ula` as the restart-surviving ownership record: one textual IPv6 address, recorded only after observing the house `/128` as usable. Reconciliation reads that record before comparing it with the current desired address. Only the recorded address may be deleted; missing or unparseable state grants no deletion authority. The delta carries the only-recorded-address restriction, explicitly makes missing state non-destructive, and adds a restart scenario covering a changed or removed guild file while the old process is gone. The legacy address, stock ULA, and unrelated interface addresses remain protected. This answers blind concerns 6, 7, and 10 without inferring ownership from a prefix.

**R2b is resolved.** Design and delta agree that usable means the desired address is present on `br-mesh` at prefix length 128, neither tentative nor DAD-failed. Publication follows that observation rather than command status or the ownership record. An add error with the correct usable address already present counts as assigned and records that address; an error leaving no usable address neither publishes it nor replaces the state file. The explicit tentative/DAD-failed scenario also prohibits recording those entries. These rules answer blind concerns 8 and 9 and preserve retry after a failed add.

**R2c is resolved.** The delta now includes cases for tentative/DAD-failed state, already-present address despite an add error, failed add with absence, missing/invalid guild input, guild change/removal, restart after change/removal, and interface recreation. The implementation tasks explicitly require parser cases, state/publication tests for those transitions, and one assignment integration check. Parsing is specified as ASCII trimming followed by exactly 64 hexadecimal digits of either case. Those acceptance obligations are sufficient for this contract review; they remain unchecked implementation work.

**Earlier R1 and R3 remain resolved.** Canonical guild bytes, domain separation, distinct router/app identity encodings, network byte order, subnet ids, and the zero-IID clamp are explicit in design and delta. I independently recomputed all six design-table fixtures with Python BLAKE3 and compared parsed IPv6 values; every value matches. The domain is exactly 20 bytes. The modified requirement states the probabilistic collision limits rather than promising universal uniqueness.

## Steelman against the blind take

Blind concern 4 is satisfied by preserving the legacy `/64`, not by requiring the new house address to use `/64`. The author's separate house `/128` deliberately avoids installing a covering house route while retaining current on-link legacy management. Together with the unchanged IPv4 underlay, Iroh exclusion, Babel deny, and interface placement, that is a coherent migration boundary. A house address remains neither a reachability claim nor authorization for foreign-house admission.

Likewise, the ownership record is intentionally narrower than a complete inventory of IPv6 addresses. If state is missing, leaving an old address behind is the conservative consequence of the explicit no-deletion rule. Requiring broad orphan discovery would undermine the safety boundary and is unnecessary to close R2a. The amended lifecycle contract answers the blind concerns without requiring a watcher, collision allocator, routing change, or new state service.

The design's `Unverified hypotheses` section says none. A focused assignment-state spike remains available before implementation if needed; cross-site forwarding is explicitly a later change and is not a premise of this acceptance.
