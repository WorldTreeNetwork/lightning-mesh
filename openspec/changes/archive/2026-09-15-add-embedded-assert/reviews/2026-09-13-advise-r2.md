## Blind take

1. Pin each request to a registered card controller, its exact `WindowProxy`, its normalized entry origin, and a document-generation value captured when the message arrives.
2. Refuse approval and silent signing if an iframe `load`, removal, replacement, origin mismatch, or controller teardown changes that generation; revalidate immediately before signing, not only before posting.
3. Pin delivery to the captured requesting window with the exact origin, and never retarget a response to whichever document or same-origin sibling occupies a card slot later.
4. Refuse all bridge and `/assert` work whenever hello.mesh is framed, including by hello.mesh itself; this guard must run before listeners, identity reads, approval reads, or redirects that disclose state.
5. Refuse bridge registration for every card the contract forces to link out: IP literals, reserved `hello.mesh`/`id.mesh`, opaque origins, and any URL whose host is not an accepted non-reserved `.mesh` name.
6. Treat server-fetched manifest names and metadata as attacker copy only; derive authority from the card's already-validated entry URL and show the exact origin first in trusted chrome.
7. A single global consent slot must preserve a displayed source/origin/nonce tuple, but it also needs deterministic cancellation or timeout so one hostile card cannot indefinitely deny identity to every other card.
8. Specify what happens to simultaneous cross-card requests and whether silent requests can proceed during visible consent; no path may overwrite state, inherit another card's gesture, or create misleading responses.
9. Make the trusted “Identity shared with <origin>” indicator atomic with successful silent delivery and clear or rebind it on navigation/removal so it never describes a different document.
10. Tradeoff: global serialization makes consent attribution auditable, but bounded expiry and fail-closed rejection are preferable to an unbounded queue that turns one user decision into stale signing later.

The ten lines above were written before opening either change's amended
`design.md`, `tasks.md`, or delta spec.

## Comparison and steelman

The amended design keeps the right core: the host accepts only a registered
card's exact source and entry origin, derives the audience rather than trusting
the message, signs the unchanged fixed v1 payload, and returns only the public
identity assertion with an exact `targetOrigin`. Consent stays in trusted
hello.mesh chrome and the manifest name remains explicitly self-claimed. The
single global consent slot is also a simple, auditable answer to gesture/state
confusion, provided it has a bounded lifecycle.

The dependency strengthens rather than weakens that boundary. Its delta
requires card insertion only for a non-key-bearing entry origin: IP literals,
reserved `hello.mesh`/`id.mesh`, and the current page origin link out
(`add-mini-app-contract/specs/mesh-mini-apps/spec.md:107-123`), with explicit
gateway-IP and reserved-name scenarios at lines 137-153. Entry URLs remain
derived from the service record, and bridge receive/send checks use the exact
iframe window and entry origin (lines 155-170). Server-side manifest fetching
does not turn manifest data into authority: fetching is bounded to the record's
mesh address (lines 38-63), and names remain inert presentation text. These
amendments do not reopen audience spoofing or expose the secret key.

## Round-1 closure audit

1. **Framed silent signing — closed in the delta.** The requirement now makes
   `window.top !== window` fail closed before identity load, approval reads,
   bridge registration, or signing, and applies it to both transports including
   previously approved `prompt=none`
   (`add-embedded-assert/specs/mesh-mini-apps/spec.md:63-66`). The `/assert`
   regression is named at lines 78-82, and the owed implementation/test task is
   present at `tasks.md:16`.
2. **Request-document binding — not fully closed.** Exact card/window capture,
   removal/replacement handling, same-origin sibling delivery, and
   navigate-away-and-back cases are now specified at delta lines 15-18, 47-51,
   107-109, and 123-127. However, invalidating only when the iframe's next
   `load` fires leaves a real pre-`load` delivery race, detailed below.
3. **Cross-card consent confusion — closed, with a new availability
   regression.** One global pending record, immediate rejection of another
   card, and binding Allow to the displayed card/origin/nonce are explicit at
   delta lines 15-21, 41-45, and 55-60. That prevents state overwrite, but an
   unbounded pending request lets one card deny the facility to all others.
4. **Silent ambient disclosure — closed.** Every successful `prompt:none`
   issuance must show the precise origin in trusted card chrome and must not
   claim app-session success (delta lines 110-115), with the observable scenario
   at lines 129-133. The design also records the `ncy.3` shipping dependency at
   `design.md:69-71`.
5. **CSP/captive-portal scope — closed.** CSP is limited to SPA/static
   application HTML and explicitly excluded from `PORTAL_HTML` and byte-exact
   probe bodies (delta lines 67-70), with presence and captive round-trip
   scenarios at lines 84-94.

## Send-back findings

1. **An iframe `load` event is too late to bind the response to the requesting
   document.** A newly navigated same-origin document can execute script and
   receive `postMessage` before its subresources finish and before the parent
   iframe's `load` event fires. During that interval the pending record at delta
   lines 15-18 is still valid; if Allow runs, lines 107-109 permit posting to the
   surviving `WindowProxy`, and exact `targetOrigin` accepts the new document
   because it has returned to the entry origin. That contradicts the promised
   outcome at lines 47-51. Bind success delivery to the requesting document with
   a document-scoped channel (for example, a transferred `MessagePort`) or an
   equivalent mechanism that cannot survive navigation; keep `load` invalidation
   as cleanup, not as the sole proof. Add a regression where the replacement
   same-origin document is already message-capable before the parent's `load`
   handler runs and prove it receives no token.

2. **The global pending rule is an unbounded cross-card denial lever.** Under
   delta lines 15-21, card A can open one consent request and remain inserted;
   every request from card B then receives `interaction_required` indefinitely.
   The design's spam row (`design.md:15-16`) calls this protection, but it only
   prevents a second sheet—it does not bound monopolization, and A can resume
   prompt spam after a denial. Specify a host-owned expiry/cancellation lifecycle
   and a bounded re-prompt policy so an unattended or hostile card cannot retain
   the global slot forever. Test that B can obtain consent after A times out or is
   dismissed, and that A cannot immediately reacquire the slot in a denial loop.

3. **The frame-refusal test and implementation task still leave the
   same-origin case implicit.** `frame-ancestors 'self'` deliberately allows
   hello.mesh to frame hello.mesh, so the runtime guard—not CSP—is the only
   defense there. The delta's text covers every frame, but its sole explicit
   scenario uses foreign `evil.mesh` (lines 78-82), while the original task still
   says only “do not render approve controls” (`tasks.md:9`), the exact ordering
   weakness round 1 rejected. Consolidate the task around the stronger fail-closed
   rule at `tasks.md:16` and name same-origin self-frame regressions for both the
   bridge and a previously approved `/assert?prompt=none` path.

## Disposition

Send back for document-bound delivery across navigation, bounded global-pending
lifecycle, and explicit same-origin frame-guard coverage. The unchanged v1
payload/verifier, origin-derived audience, name-host-only insertion rule, and
server-side manifest discovery are sound and should remain.
