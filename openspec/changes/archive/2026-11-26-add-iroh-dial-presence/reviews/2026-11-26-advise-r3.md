## Blind take

Written to this file before I opened the delta, `design.md`, `tasks.md`, or either earlier review. Inputs were `proposal.md` and the code at `1a55cc7`. Two deviations: I read all of `proposal.md`, not only Why, and the packet named R5 and the cap anchor, so the take was not blind to the cap.

1. Pin the preimage byte for byte: `mjolnir-iroh-dial:v1\n<challenge>\n<port>\n<ip>\n<signed_at_ms>`, dotted-decimal address, unpadded decimals, lowercase hex, `verify_strict`.
2. Pin the key: the endpoint id is the Ed25519 verifying key. It is not a `.mesh` name and not a `ServiceEntryV2`.
3. Pin the address rule in two layers. Every checker requires a `10.42` host that is not `.0`, `.1`, or `.255`. Only hello can require that the address is the TCP peer; gossip can re-check the signature and the range, never the peer.
4. Pin freshness as 90 s behind and 120 s ahead on each checker's own clock, at hello, at `apply`, in the projection, and in lookup.
5. Pin last-writer-wins: a strictly newer `signed_at_ms` replaces, an equal or older one changes nothing and is not gossiped again.
6. Pin the cap as two different checks. hello counts live records under other ids at the claimed address in the projection file and refuses at 8 or more, on every POST, renewals included. meshd `apply` checks the cap only for an id that is not yet in the book. An id already in the book that moves onto a full address skips the meshd check, so nine live hints at one address is reachable, and hello then refuses every renewal there until one fades.
7. Pin the fail-open: when the projection cannot be read or parsed, hello does not apply the cap.
8. Refuse any sentence that says a renewal is always accepted, that the cap bounds the whole book, or that the hint authenticates the peer. Refuse a relay URL field and a listing.
9. Refuse any claim of persistence. The book is memory-only; refill after restart is the client's renewal plus the re-announce on every fourth 5 s tick.
10. Tradeoff: hello reads a projection that lags the book by up to one sweep. The cap is approximate at the door and exact for new ids in the book. That avoids IPC and costs a window where an over-cap POST gets 200 and is then dropped at ingest.

## Notes that do not gate

**n1. "Until enough hints fade" names one way out.** The count at an address also drops when one of its ids renews from a different address, because the book keeps one row per id. I read the sentence as a rule for the state "holds 9 or more". Once a move brings the address to 8, that state has ended and the renewal sentence applies, so there is no contradiction with the code. "Until fewer than 8 other live hints remain at that address" would cover both exits.

**n2. The new scenario's WHEN does not say where the POST comes from.** The sibling scenario says "from that address". A POST for `10.42.2.20` from any other peer is 400 with `address does not match the client`, a different error. "Valid" carries it. The test for this scenario has to POST from `10.42.2.20`.

**n3. "Renewal" is not defined in the paragraph.** The sentence is exact when the id has a live hint at that address in the projection, which is what the two renewal scenarios set up. An id whose hint has faded is counted like a new id, and is refused when the address holds 8.

**n4. "Holds 9 or more" is hello's view, which is the projection.** The paragraph's first cap sentence says "the projection already holds", and the sentence after this one carries the unreadable-projection exception. Read together they match the code: when the file cannot be read or parsed, hello does not refuse, whatever the book holds.

**n5. An over-cap claim can get 200 and never enter the book.** Two new ids POST from one address in the same 5 s tick while the projection shows 7 others. hello accepts both. The sweep applies one and the book's cap rejects the other. The delta does not promise that a 200 means the hint will resolve, so no sentence is false. A client that needs to know should GET its own id after the next tick.

**n6. r2's notes still stand.** The restart scenario still says "a peer's re-announced hint" (r2 n1). A tick still has no length in the delta (r2 n2). The lockout at nine still needs a bead or a line on `mjolnir-mesh-23ks.5` (r2 n3). I did not file one: my write paths are this file and `tasks.md`.
