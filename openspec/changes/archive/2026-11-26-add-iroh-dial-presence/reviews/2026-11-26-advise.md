## Required edits to the delta

**R1. Projection rewrite is mis-scoped.** The delta says "Only an insert or an update SHALL rewrite the projection." That is true of the gossip arm only (`mjolnir-meshd.rs:1190`). The sweep rewrites the projection on every 5 s tick, whatever the outcome (`mjolnir-meshd.rs:2942`). The delta's own scenario "Restart does not revive a socket" depends on that per-tick rewrite, so the requirement contradicts its scenario. Scope the sentence to gossip receipt and say the sweep rewrites each tick.

**R2. Gossip re-verify is under-stated.** The delta says receipt "SHALL verify the signature and the address rules again." The code runs the whole of `apply`: port, address, encodings, signature, the clock by the receiver's own clock, last-writer-wins, then the book cap for a new id. `design.md` section 7 says this; the delta drops port, clock, and cap. The clock sentence in the delta sits under a requirement titled "at hello", so a reader of the folded spec would not apply it to receipt. The receiver's clock check is the only replay bound past hello. State the full list, and state what receipt cannot check: that the address was the TCP peer, and that the challenge was issued. `design.md` already has that sentence under "What follows".

**R3. Re-announce is missing.** Every fourth tick each node republishes its whole live book, including rows it learned from peers (`mjolnir-meshd.rs:2963`). This is how a restarted or lossy node refills a book that is never persisted. The delta does not mention it, and the restart scenario's THEN says the book stays empty "unless a new spool file validates", which leaves out that peers refill it. Add the behavior and correct the THEN. The cadence can stay out as tuning.

**R4. hello's half of the cap difference is only in the design.** The delta says hello rejects "a new endpoint id" at a full address. The code refuses any id that is not already counted at that address, including a known id that moves there (`projection_source_at_cap`, `iroh_dial.rs:242`). The delta states the book's half with a scenario and leaves hello's half to `design.md` section 4. Word the hello rule by address, not by "new", and add the mirror scenario: a known id moving onto a full address is 400 at hello.

## Blind take

Written to this file before I opened `design.md`, `tasks.md`, or the delta. One deviation: I read all of `proposal.md`, not only Why, before writing it. Inputs were the proposal, commit `1a55cc7`, `main.rs:99`, and `sync.rs:114`.

1. Pin the preimage byte for byte, port before ip, lowercase hex, unpadded decimal, strict verify, endpoint id is the signing key.
2. Pin which check lives where. Peer equality, the challenge, and unknown-field refusal exist only at hello. The book and gossip re-check signature, address class, port, and the clock window.
3. Pin the clock window as asymmetric, judged by each checker's own wall clock.
4. Pin last-writer-wins as strictly newer.
5. Pin the cap as two different rules, hello's and the book's.
6. Pin the memory book: starts empty, never restored, re-announced every fourth tick, live-only projection, one-id lookup that returns the signed row.
7. Pin the wire position: appended, discriminant 15, older nodes skip.
8. Refuse any sentence that says gossip checks the peer address or the challenge, that the cap is one rule, that the clock is two minutes both ways, or that relay fallback is a requirement while `mjolnir-mesh-23ks.2` is open.
9. Refuse a relay field, a list route, and a restore from disk.
10. Tradeoff: freshness is the client's wall clock judged by each router's wall clock. It buys a stateless re-check on gossip and expiry with no persistence. It costs the hint on any router whose clock is off by more than the window.

## Notes that do not gate

**N1. The clock bullet in the design is wrong for the node that matters.** `design.md` says a node with an off clock "drops the record locally. Other nodes are unaffected." If that node is the client's own gateway, hello answers 400 and nothing is spooled or gossiped, so no node gets the record. The client does see an explicit error, which is the saving grace. Two follow-ups:
- `docs/deploy/mesh-app-publishing.md` in `1a55cc7` says "within two minutes of the router". The code allows 120 s ahead and only 90 s behind.
- For `mjolnir-mesh-23ks.3`: confirm fleet nodes hold wall time when the uplink is down. I found no NTP or clock configuration under `deploy/openwrt/`. I did not inspect the image defaults, so this is an open question, not a finding.

**N2. The spool-write race the driver left out is real in the code's structure.** hello writes the spool file in place with `std::fs::write` (`routes.rs:748`), with no temp file and rename. A sweep that reads between truncate and write gets an empty file, fails to parse it, and renames it to `.json.bad`. The POST has already returned 200 and the claim is lost until the next renewal. `.json.bad` files are never removed. I read this from the code; I did not reproduce it. It does not make any delta sentence false, but the delta now pins the `.json.bad` rename as a SHALL, so the race should have a bead before fold. I did not check whether the name-claim spool has the same pattern.

**N3. No bound on the whole book.** The cap is per address. A client that can open TCP from many addresses in its `/24` can hold about 2,000 rows (253 hosts by 8). Every node re-announces every row every 20 s, and hello parses the whole projection on each POST and GET. The 90 s fade means the load must be sustained, and the record is only a hint. Worth a stated bound or a bead.

**N4. A mesh member can fill any address's cap.** Receipt cannot check peer equality, so a member node can publish its own keys at a victim's `10.42` address mesh-wide and block the victim's new id. Members are trusted routers, so I read this as inside the threat model. The sentence R2 asks for makes it visible.

**N5. "The GET handler SHALL NOT re-verify the signature"** is true of the code but pins an absence as a prohibition. A later hardening would break the spec. "Does not re-verify; the row carries `sig` and `challenge` so the caller can" says the same without forbidding it.

**N6. Fallback wording in the commit.** The module doc (`iroh_dial.rs:14`) and the shipped doc state that address lookup supplies the home relay when the socket does not answer. The epic says that has no spike finding. The delta correctly leaves it out. I accept the commit without that claim.

**N7. Scenario title "Ninth other endpoint"** describes the ninth endpoint with eight others live. The test name `eighth_other_endpoint_from_one_address_is_refused` has the same slip.
