## Blind take

Written before opening design.md, tasks.md, or the prior review; based on the proposal Why, living permit spec, current ADDED delta, and cited code.

1. Pin authorization to the verified two-direction permit result; keep the predicate free of route side effects.
2. Pin local house identity to Session.guild captured at open, with no guild parameter on sync.
3. Refuse this house's own /48 and pairs unrelated to the open session, including prefix collisions with its own house.
4. Install only foreign /48 device routes on a live TUN; never assign those prefixes as interface addresses.
5. Treat omission from the presented pair set as desired route removal, without inventing a withdrawal op.
6. Retain ownership when deletion or subsequent observation leaves absence unconfirmed, and report an error for retry.
7. Confirmed absence may release ownership even when the delete command itself failed because the route already vanished.
8. A successful route install followed by failed observation must remain tracked so a later omitted pair can still remove it.
9. Verify both failure recovery and session-house binding through tests that inspect ownership and actual route state.
10. Tradeoff: caller-driven reconciliation keeps the slice small, but requires honest error propagation and conservative tracking of uncertain OS state.

## Comparison and steelman

The two prior findings are addressed in the current code. The deletion loop at `admin/src-tauri/src/app_tun.rs:71` retains an owned prefix when observation reports presence or fails, and returns `Err`; confirmed absence drops it. This correctly handles a delete reporting failure because the route was already absent. The test at line 496 now exercises failed deletion followed by successful cleanup. The session captures `guild` at open (line 326), sync takes only pairs (line 61), and `prefixes_for_house` excludes the opening house's own prefix (line 122). The pure fixture exercises unrelated pairs and an own-prefix collision. Those two previously completed owed boxes can remain checked.

The strongest case for acceptance is the deliberately small boundary: validated pairs arrive from the caller, routes belong to an existing session, and no new authorization mechanism, withdrawal kind, watcher, Babel export, or overlay demux is needed. I retain the prior acceptance of that scope and the trusted provenance of `AdmittedPair`. The device-route command does not assign a /48. The design's `Unverified hypotheses` section says none; a spike remains optional before act.

That scope does not excuse forgetting a route the session successfully wrote. The design promises to delete a session-installed prefix when it disappears from the presented set. Returning an error on installation observation is useful, but does not discharge that cleanup responsibility when the caller's next set changes.

## Owed before acceptance

1. **Retain cleanup ownership after successful installation with failed observation.** At `admin/src-tauri/src/app_tun.rs:110`, `Err(())` from `route_present` only sets `failed`; it does not put the prefix into `kept`. Line 116 therefore forgets it even though `ip -6 route replace` already succeeded. Concrete trace: start with no owned prefixes; sync a valid A/B pair; the replace installs B's /48; the subsequent route-show command fails; sync returns `Err` with no ownership recorded. On the next sync, observation works again but the caller presents an empty pair set. Both loops are empty, sync returns `Ok`, and B's route remains installed for the live session. Repeating the empty sync never repairs this. This violates the delta's omission-removes-route requirement.

   Keep a successfully written route tracked while its presence is uncertain, or confirm rollback before releasing responsibility. Preserve error reporting and retry behavior; confirmed absence can release ownership. Add a focused regression that makes replace succeed and the following observation fail, then omits the pair and verifies cleanup. Also exercise a failed observation after deletion followed by confirmed absence, which the revised code handles but the current test does not cover. This is one ownership transition fix within the existing contract, not a request to expand admission or routing scope.
