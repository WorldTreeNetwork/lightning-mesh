## Independent blind take

These ten lines were written in the review session before opening the delta, `design.md`, or `tasks.md`, from the proposal, living spec, cited code, and spike evidence. They are reproduced unchanged here. The prior review was opened only after the comparison below had begun.

1. Pin connection identity to `router_ula(local guild, authenticated peer id)`.
2. Preserve Babel’s link-local neighbor semantics without reversing them into `10.254`.
3. Require a cold-start path that establishes Iroh before overlay routes exist.
4. Authenticate the association between a Babel next hop and its carrying connection.
5. Remove stale associations on disconnect, route withdrawal, and house change.
6. Preserve IPv4 payload forwarding while replacing its connection lookup key.
7. Refuse outer Iroh traffic through `mjolnir0`, including routes to peer house addresses.
8. Bind only a usable house `/128`, clear default IP transports, and fail closed on address loss.
9. Preserve unrelated ULA assignment, admission, publication, and operator-reference requirements.
10. Accept the availability cost of waiting for a usable house address in exchange for deterministic transport identity.

## Comparison and steelman

The local-guild plus authenticated-endpoint derivation now identifies the connection key precisely. Hello/IHU reception supplies the scoped link-local association, and ambiguity selects nothing. The same-house transit scenario correctly separates the foreign destination from its next-hop key. IPv4 stays IPv4 and resolves through the announcing neighbor. Link-local unicast can return on the associated connection before destination host routes exist, while Babel multicast reaches every established connection. These answer the association and control-dispatch concerns; a new wire identity or a different connection key is unnecessary.

The endpoint contract now supplies startup ordering, retry, close/rebind behavior, interface recreation, explicit-bind handling, and mode coverage. I verified `clear_ip_transports` in the local Iroh 1.0.0 source at `endpoint.rs:503`; it removes all IP transport configurations. The existing spike's successful bind/dial remains evidence for that narrow claim, and the design accurately acknowledges that it did not clear the IPv4 socket or exercise recovery. Endpoint lifecycle implementation and tests can proceed from this contract once the routing gap below is resolved.

The full requirement comparison preserves address usability, recorded-address cleanup, admitted-prefix filtering, Babel restart retries, and gateway-default rules. The operator-reference requirement remains outside this delta as instructed. The stale walked fleet column is an acknowledged scope boundary, not a new owed inventory rewrite.

The strongest case for acceptance is that the new SHALLs already demand direct `br-mesh` bootstrap and prohibit outer traffic on `mjolnir0`, with scenarios for both. An implementer could choose underlay Babel routing or transport-specific routing while satisfying those outcomes. I agree that exact commands, maps, retry machinery, and a new successful spike need not be prescribed here. However, those two routing approaches differ on route ownership, startup dependencies, and the retained Babel-only reachability rule. That choice is still an architectural contract, rather than a parser or socket-builder detail. The current cold-start scenario puts “a connection is established” in WHEN and consequently does not establish the prerequisite it is meant to verify.

## Owed before fresh advise

### R4 — Finish R2's underlay bootstrap and route separation contract

The delta requires the first dial to be on-link on `br-mesh`, with a relay alternative for off-link peers. It also retains “Assigning the house `/128` SHALL NOT make any other address in that prefix on-link” and “Another house `/128` SHALL be reachable only as a Babel host route.” These can be reconciled if the first route is learned by independent underlay Babel, but neither the design nor the scenario says that this is the chosen source or when it becomes available. If an explicit per-peer transport route is intended instead, its relationship to the Babel-only clause needs to be stated.

This matters especially in LAN overlay mode: relays are disabled by default (`mjolnir-meshd.rs:391` onward), while the current overlay reconciler renders only the overlay interface (`:8589` onward). The current non-overlay path can run Babel on shared-L2 interfaces (`babel/config.rs`, `BabelConfigInputs::l2_interfaces`), but that does not establish an independent `br-mesh` route in every mode covered by the new rule. The spike supplied peer host routes manually (`docs/spikes/iroh-ula-dial/src/main.rs`, `setup`); those routes are an input to its successful dial, not evidence that daemon startup creates or learns them.

Specify who supplies the peer `/128` underlay route, its interface/table scope, and its startup dependency in LAN and overlay modes. Reconcile that choice with the retained Babel-only clause. State how outer transport selects that independent path when the same peer `/128` has an overlay Babel route, while inner host traffic still follows Babel, and what happens when the independent path disappears. The existing `OverlayRouter::next_hop` anti-recursion drop (`mjolnir-meshd.rs:8345`) cannot simply become a drop of all house-host packets because this change explicitly forwards those packets. Naming `mjolnir0` as forbidden is a useful invariant; the design still needs the rule that separates the two uses of the same destination.

Add one isolated cold-start acceptance journey with relays disabled, only the specified initial address/configuration state, no manually preinstalled peer route, and no existing Iroh connection. It should establish the chosen underlay route, complete the first dial, exchange Babel Hello/IHU, and forward IPv4 and IPv6 traffic. Then install/prefer the peer `/128` route on `mjolnir0`: outer UDP must continue on the independent path (or explicitly fail closed when that path is unavailable), and inner host traffic must still work through Babel. The fixture may use namespaces or another isolated arrangement; no fleet errand or deployment is requested. Implementation and execution of this check belong to act, after the contract names the route source and separation rule.
