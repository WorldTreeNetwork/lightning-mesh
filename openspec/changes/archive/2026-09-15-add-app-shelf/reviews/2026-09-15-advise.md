## Verdict on the packet contrast

The delta pins every clause the packet asked for: tiles only from
`isMiniApp`; `/api/apps` is decoration, else service name + `embed: link`;
no iframe before tap and insertion defers to the living Sandboxed
insertion (so `canEmbed` gates it); manifest strings as text or `<img>`;
page load reaches only a hello.mesh origin; unmarked services stay in
Services. No missing constraint would put app script in a hello origin or
fetch an app host before tap. Identity and publish are not touched.
Accept, with one wording fix and the pins below to apply before code.

## Must fix before code (wording, not design)

**Stale ≠ link-out.** Delta: "A missing, stale or invalid manifest SHALL
still show a link-out tile." The node sets `stale: true` whenever the last
refetch errored *or* the last-good is expired, and it deliberately keeps
the last-good manifest for up to 1 hour in the errored case
(`apps.rs` `response()` and the `keep` branch; `contract.ts` carries it as
`MiniAppRecord.stale`). Read literally, one transient fetch failure flips
a card app to link-out for at least a refresh cycle, and the keep-last-good
rule in the living spec becomes dead. Reword to: "A record with
`manifest: null` (missing, expired or invalid) SHALL show a link-out tile.
A record with `stale: true` and a kept manifest SHALL honour that
manifest." Optionally show a muted "may be out of date" hint; nothing
more.

## Pins the delta should state (each is one sentence)

1. **Join direction.** The tile set is the directory filtered by
   `isMiniApp`; `/api/apps` is looked up per service. If the `/api/apps`
   request itself fails or is not yet loaded, tiles still render as
   link-out. `parseAppsResponse` alone returns only apps present in the
   response, so `apps.ts` must not use it as the source set.
2. **Entry URL provenance.** Iframe `src` and link `href` come only from
   `entryUrl(record.service)`. Nothing in the `/api/apps` record is ever
   used as a URL (the response carries none today; keep it that way).
3. **`pageOrigin` is `window.location.origin`**, never the literal
   `hello.mesh`. Pages are also served at `10.42.x.1`, and same-origin
   refusal in `canEmbed` only works with the real origin.
4. **Link-out anchor.** `target="_blank" rel="noopener noreferrer"`. Link-out
   is allowed to IP-literal and reserved hosts; only framing is refused.
5. **No link hints.** The "only hello.mesh origins on load" clause should
   also forbid `<link rel="preconnect|prefetch|dns-prefetch|icon">` to
   entry origins. The Playwright check should assert no `<iframe>` in the
   DOM and no such `<link>` in `<head>`, not only the request log.
6. **Close removes.** Closing a card removes the `<iframe>` element and its
   `message` listener. Hiding or clearing `src` is not enough.
7. **Bridge wiring is in scope of the card.** The living Bridge envelope is
   SHALL. Tasks do not mention it. The card wires one `message` listener →
   `acceptBridgeMessage(event, frame.contentWindow, entryOrigin)`; sends
   `init` once after the first `ready` via `sendBridgeMessage` with
   `targetOrigin = entryOrigin`; applies `resize` through `clampHeight`;
   handles `open` via `window.open(url, '_blank', 'noopener')`. Add a task
   line and a vitest for listener teardown.
8. **Tile always shows the entry host as text** (e.g. `keyed.mesh:3000`)
   beside the manifest `name`. Manifest names are attacker-chosen text; a
   tile named "hello.mesh" or "Identity" must not be able to fully
   impersonate. Cheap now, matters more once `ncy.4` lands.
9. **Marked apps and Services: choose.** The delta only says unmarked stay.
   Say whether `isMiniApp` services are removed from Services (my
   recommendation: yes, Apps now owns the walk-up "find KEYED" job that
   `kgq` gave Services) or duplicated. Either is fine; unstated is not.
10. **Poll cadence.** `/api/apps` refresh rides the directory poll (5 s) or
    slower, never faster. It is a cache read on the node, so cost is
    bandwidth on phones, not fetch pressure on app hosts.

## Tradeoffs (author's call, just record it)

- **One card open at a time vs many.** One-at-a-time bounds memory on
  phones and makes bridge state trivial; cost is close-then-open. Pick one.
- **Empty Apps panel above Services** is noise on the common no-app mesh.
  Prefer a compact single line (or collapsed panel) that does not push
  Services down, rather than a full empty card.

## Blind take (unchanged, written before tasks.md and the delta)

1. Pin: tile source is directory services filtered by `isMiniApp`, decorated by `/api/apps`. `parseAppsResponse` only returns apps present in the response, so an app the node has not fetched yet (or when `/api/apps` fails) must still be a link-out tile, not dropped. Shelf = directory-derived set, response is decoration only.
2. Pin: page load adds exactly one request, `GET /api/apps` on the page origin. No `<link rel=preconnect/prefetch/icon>` to entry origins, no favicon probe, icons only as the validated `data:` URI already in the record.
3. Pin: no `<iframe>` element exists in the DOM before tap. Not hidden, not `src=""`, not `srcdoc`. Tap → `canEmbed(entryUrl, location.origin, manifest?.embed)` → iframe with `FRAME_SANDBOX/FRAME_ALLOW/FRAME_REFERRER`; closing a card removes the element, not just hides it.
4. Pin: link-out is `<a href={entryUrl} target="_blank" rel="noopener noreferrer">`. Open-in-tab is allowed for IP-literal and reserved hosts (new tab, no key access); only framing is refused.
5. Pin: `manifest === null`, `error` set, or `embed: link` → service name, link-out. `stale: true` with a kept manifest → still honours `embed` (spec keeps last good for 1h). Must be stated so the UI does not invent a third "stale" mode.
6. Pin one answer to: do marked apps also remain in Services? Proposal only says unmarked stay. Either dedup (Apps owns them) or duplicate; the delta must choose. I would dedup, since "Services above topology" exists to find apps like KEYED and Apps now does that.
7. Refuse: any `{@html}`, `innerHTML`, `srcdoc`, or manifest string in an attribute other than `<img src>` / text nodes. `name`/`description` render as text only.
8. Refuse: a browser poll of `/api/apps` faster than the directory poll. It should ride the same cadence (or slower); the node's 5-minute refetch is independent and the browser cannot speed it up.
9. Refuse: a second bridge listener implementation. Per-card `message` listener → `acceptBridgeMessage(event, frame.contentWindow, entryOrigin)`; `init` once after first `ready` via `sendBridgeMessage` with `targetOrigin = entryOrigin`; listener removed on close.
10. Tradeoff: many cards open at once vs one at a time. One-at-a-time bounds memory on phones and makes the bridge state trivial; the cost is close-then-open. Either is acceptable if pinned. Second tradeoff: an empty Apps panel above Services is noise for the common no-app mesh; prefer a compact empty line that does not push Services down.

## Steelman of the delta against the take

Take items 2, 3, 4 (`error` → link), 7 are already in the delta or follow
from "insertion SHALL follow Sandboxed insertion". Item 1 is implied by
"when present, else service name" but the join direction is not explicit.
Item 5 is contradicted (see Must fix). Items 6, 8, 9 are silent. The
delta's "empty directory SHALL show an empty Apps state, not Services'
empty copy" is a good catch I had not made. The delta is thin because the
contract is living; that is the right shape. Nothing here reopens
insertion or sandbox.
