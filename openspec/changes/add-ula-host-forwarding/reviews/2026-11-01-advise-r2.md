## Independent take (written before opening design.md or tasks.md)

1. Pin the house address to a usable `br-mesh` `/128`; a guild file or stale state record alone must not enable export.
2. Pin both Babel render paths to the same current house address and remove old permissions after loss, replacement, or restart.
3. Refuse covering house routes or on-link assumptions: another router is reached through its individual Babel host route.
4. Pin house `/48 eq 128` permits ahead of the blanket ULA denies, while leaving legacy and stock ULA redistribution closed.
5. Refuse a global ban on `le`: the existing gateway IPv4 default export must survive this change.
6. Pin IPv6 destination selection to an exact current `/128` route with an overlay-shaped `fe80::H` next hop.
7. Resolve that next hop through the existing `10.254` connection index; refuse direct `fd` dialing or inferred destination-to-peer mappings.
8. Pin snapshot replacement on polling so withdrawal removes selection; a missing route or missing connection must drop unicast.
9. Preserve the IPv4-only mirror and existing link-local control path; require positive, wrong-peer, unknown-destination, and withdrawal checks.
10. Tradeoff: a separate host-only IPv6 map is bounded and auditable but inherits polling delay; that delay must not become an indefinite stale route.

## Comparison and steelman

The amendment answers the take without requiring a different routing architecture. A separate exact-host map leaves the IPv4 `Fib` and its `ip -4 route` input intact. The IPv6 route supplies the next hop; the existing connection index supplies the live connection. This fits `OverlayRouter::next_hop` and `resolve` (`mjolnir-meshd.rs:8327–8375`), while snapshot replacement follows the existing mirror pattern (`:8421–8446`). The specified overlay-shaped next hop must be checked as that shape, rather than copying the current destination branch's loose first-segment check. A route to a disconnected peer still fails at the connection lookup.

The strongest objection to my take is that exact host forwarding does not require enumerating authenticated remote hosts. The house `/48 eq 128` filter bounds route length without installing a covering prefix or proving host ownership. That is sufficient for this node; foreign admission and transport migration remain outside it. The map may follow installed host routes, with Babel responsible for house policy.

Existing config-change restart paths (`mjolnir-meshd.rs:7990–8030`, `:8590–8623`) provide the integration point.
