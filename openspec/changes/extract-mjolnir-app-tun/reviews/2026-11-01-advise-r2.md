## Blind take

Written before opening design.md or tasks.md, from proposal Why, the two living specs, the ADDED delta, and their cited session, encap, and address code.

1. Pin a reusable session crate that another desktop app can use without Admin or the router dependency tree.
2. Preserve the exact subnet-1 app address derivation, one Linux TUN at MTU 1280, local `/128`, and peer device `/128`.
3. Keep one caller-supplied connection bound to the requested peer; refuse fallback connections or Iroh endpoint creation.
4. Require explicit `EncapHandles::abort` on either task return; dropping join handles cannot satisfy sibling cancellation.
5. Require Session Drop to abort both encap tasks before removing owned state, including before the supervisor first polls.
6. Keep address reporting independent of liveness, with up false after failure and on non-Linux, and preserve route-install rollback.
7. Keep ownership of admitted `/48` routes through failed deletion or uncertain observation, so later sync can retry.
8. Preserve the opened house identity and keep signed admission filtering in Admin; refuse a caller retargeting an existing session.
9. Refuse covering-address assignment, Babel or Iroh bind changes, UI expansion, and router forwarding work in this extraction.
10. Tradeoff: accepting prefix bytes makes the crate reusable but shifts admission policy to its caller; test that boundary and both pending-task directions plus early Drop.

## Comparison and steelman

The amended design answers the lifecycle concern explicitly. It preserves the landed address and route shape while rejecting the landed cancellation behavior. The current supervisor drops `tx` and `rx` after its select (`admin/src-tauri/src/app_tun.rs:310`), and current Session Drop only aborts `watch` (`app_tun.rs:188`). `EncapHandles::abort` already provides the required operation (`crates/mjolnir-mesh/src/tun/encap.rs:95`). The locally installed Tokio 1.53.1 source, matching Admin's lockfile, confirms that dropping a join handle detaches its task.

The revised Session section now requires the session to hold the encap handles, the supervisor to abort both on either return, and Session Drop to call the same abort even before the supervisor polls. Cleanup covers the local address, peer route, and admitted routes. The ADDED delta and MODIFIED admin-app-tun requirement repeat those obligations. Their pending-receive, pending-TUN-read, and early-Drop scenarios give the implementer observable cases, and the unchecked lifecycle task requires task/resource release plus address/route cleanup. This resolves the round-one P1; the checked owed boxes record contract preparation, not test execution.

The strongest objection to acceptance is that a mechanical move still carries the current bug and that the design does not prescribe a concrete shared ownership container. That is implementation work with an explicit acceptance gate now: early Drop must retain an independent path to abort both children, and either task's return must trigger cleanup of all owned routes. The contract no longer permits copying the defective supervisor unchanged. Requiring a particular container before act would add design detail without closing a missing obligation.

For lifecycle verification, invoking abort on an already-returned task does not turn its successful result into a cancellation error. Tests should prove the pending sibling's cancellation and release, both pending tasks' release on early Drop, and owned-state removal. Tokio abort requests cancellation; tests must observe eventual task completion/resource release rather than infer it from the down flag. This clarifies how to exercise the existing gate, not an additional contract condition.

The other blind concerns are answered across the three deltas and design. The dependency direction puts address math, transport seam, and session below both consumers without Iroh or daemon features. The full Admin replacement retains address usability, failed-open rollback, down-state address reporting, immutable opening-house identity, and the guild-window restrictions. The admitted-prefix replacement retains failed-delete and uncertain-observation ownership and retry semantics.

Against my prefix-policy concern, the six-byte API is deliberately a mechanism for prefixes the caller has admitted. Admin remains responsible for selecting the pair for the opening house; the retained scenarios exclude stock, own-house, and unrelated prefixes. A reusable crate need not read or authenticate a guild log to preserve that boundary. Router forwarding, Babel, the dial pin, and publishing remain outside this change.
