## Blocking finding: reconcile task ownership before extraction

**P1 — `design.md:11` promises the landed runner's supervision, but the cited runner does not implement the retained abort contract.** In `admin/src-tauri/src/app_tun.rs:310–320`, either encap task completing leads to `drop(tx)` and `drop(rx)`, not cancellation of the remaining task. In `app_tun.rs:188–204`, session Drop aborts only `watch`; that drops its child join handles without aborting their tasks. `EncapHandles` supplies an explicit `abort()` but has no abort-on-drop implementation (`crates/mjolnir-mesh/src/tun/encap.rs:90–103`). The locally installed Tokio source confirms that dropping a join handle detaches its task (`tokio-1.53.1/src/runtime/task/join.rs`, matching Admin's lockfile).

A concrete failure is a TUN read returning EOF while `recv_datagram()` remains pending on an otherwise live caller connection. The supervisor returns and reports down, yet the receive task can retain its connection and TUN write half. Dropping an active session has the same ownership gap. Deleting the interface does not cancel a future waiting on the connection. This contradicts the retained admin-app-tun requirement that either task exit aborts its sibling and Drop performs the same cleanup; it also undermines the new crate's explicit ownership promise.

The strongest case for accepting is that the MODIFIED delta already requires correct cancellation, so an implementer could repair it while moving the code. However, the design explicitly says the moved session matches the landed runner, declares no unverified hypotheses, and tasks only move existing tests. The current packet test checks the down flag and address disappearance (`app_tun.rs:663–675`), not termination of both tasks. A mechanical extraction can therefore pass those checks while retaining this violation. Reconcile that discrepancy explicitly before act; this is a bounded correction to the existing contract, not a request for broader session redesign.

Owed preparation: describe ownership that cancels both encap tasks on session Drop, including before the supervisor first polls, and cancels the sibling on either task's return. Record focused verification for both directions with the other side held pending, plus active-session Drop. Verify task/resource release and owned address/route cleanup, not only `is_up()`. Implementation belongs to the subsequent act.
