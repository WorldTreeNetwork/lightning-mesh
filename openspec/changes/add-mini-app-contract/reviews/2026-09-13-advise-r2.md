## Independent take — blind pass

1. Pin fetch eligibility to current `ServiceEntryV2` app records already present in the local directory; no browser-supplied URL, host, port, scheme, or path may influence a fetch.
2. Pin the network destination to the record’s literal `ip:port`, the scheme to its HTTP(S) protocol, and the request target to one fixed manifest path, so the endpoint cannot become an SSRF proxy.
3. Resolve no app-controlled DNS for transport; if a service name is needed for HTTP Host or TLS SNI, connect to the record IP and reject any authority mismatch or alternate address.
4. Refuse redirects, non-GET methods, authentication, cookies, request bodies, proxy settings, response decompression that can exceed the cap, and all destinations outside the accepted mesh-service address ranges.
5. Verify TLS normally when possible; if mesh-local self-signed HTTPS must be tolerated, isolate no-verification in a manifest-only client/type that cannot carry credentials or be reused by any future sensitive client path.
6. Bound connect, header, body-read, and whole-operation time independently; stream at most 16 KiB of encoded response bytes and reject excess, non-JSON, or invalid UTF-8.
7. Keep app-host I/O off `tiny_http`’s single request loop: a bounded background worker refreshes cache entries, while `GET /api/apps` performs memory-only reads and never initiates or awaits a fetch.
8. Bound concurrency, queue length, app count, cache bytes, and refresh frequency; add jitter/backoff so a broken or malicious publisher cannot make every router hammer an endpoint in lockstep.
9. Serve last-good sanitized manifests with explicit fetched-at/stale/error metadata and an expiry policy; disappearance or mutation of the publishing record invalidates the corresponding fetch authority and cache entry.
10. Tradeoff: router-side discovery prevents pre-intent visitor disclosure and centralizes validation, but adds an HTTP/TLS client and background scheduler to a static aarch64 binary, so dependency/binary-size budgets favor a small blocking client on a dedicated thread over a general async stack.

The ten lines above were written before opening the amended `design.md`, `tasks.md`, or delta spec.

## Comparison and steelman

The node-side fetch design answers the blind-pass concerns without weakening the browser boundary. Its strongest case is that it moves unavoidable discovery traffic from a visitor-identifying endpoint to infrastructure: the browser receives inert, validated presentation data from a hello origin, while an app host sees only periodic router refreshes. The fetch is not exposed as a URL-taking request handler, and the iframe still does not exist until the visitor opens a card. That preserves useful pre-tap decoration without disclosing each visitor to every publisher.

The chosen fetch authority is narrow enough for this contract. The source is the current directory projection, the transport destination is the record's literal `ip:port`, the accepted address space is only `10.42.0.0/16` or `10.254.0.0/16`, the manifest target is fixed, an icon is restricted to a manifest-named same-origin path, the method is GET, redirects are refused, the operation times out after three seconds, and response bodies are capped. `Host` names the app's entry host but does not replace the record IP as the connection target. Read literally, [the delta's destination rule](../specs/mesh-mini-apps/spec.md#L45-L52) also excludes DNS resolution, proxy routing, or any other transport path that would contact a different address.

The background refresher is the correct fit for the cited server: `main.rs:44-89` handles `tiny_http` requests serially. [The design](../design.md#L65-L81) puts all app-host I/O on a background thread and makes `GET /api/apps` an in-memory serialization path, so a slow or malicious app cannot stall health, directory, identity, or static responses. The five-minute per-app rate ceiling and one-hour last-good expiry bound churn and staleness. The implementation should key cached authority by the complete service tuple (name, protocol, record IP, and port), prune entries that leave the current directory, update entries independently rather than waiting for an entire hostile directory sweep, and enforce body limits while streaming after any transfer decoding. Those are the conservative readings of “for every mini-app in its directory,” “record's own ip and port,” and “per app,” not a competing design.

The TLS exception is acceptable only at the boundary the amendment chose. [Design lines 71-74](../design.md#L71-L74) make the no-verification certificate policy a fetcher-only client, while [delta lines 51-63](../specs/mesh-mini-apps/spec.md#L51-L63) keep its outputs presentation-only and schema-validated. The act should keep that client private to the manifest/icon module, with no credentials, cookies, ambient authentication, exported client handle, or reuse by later authority-bearing HTTP calls. This satisfies the packet's no-leak condition; a process-global or general-purpose insecure client would not.

The static-router cost is real but acknowledged. `mjolnir-hello` currently has no HTTP client, and `deploy/openwrt/build-hello.sh` produces a static aarch64-musl binary, so adding `ureq` plus rustls must be measured as [design lines 78-81](../design.md#L78-L81) require. The plain-HTTP fallback described there is not silently interchangeable with the accepted delta: taking it would contradict the self-signed-HTTPS scenario at [delta lines 77-81](../specs/mesh-mini-apps/spec.md#L77-L81) and therefore requires an explicit change amendment if the measured binary cost is rejected.

## Round-1 closure

1. **All key-bearing gateway origins are refused.** [Delta lines 109-123](../specs/mesh-mini-apps/spec.md#L109-L123) classify every IP-literal host as key-bearing, in addition to reserved hello names and the current origin. [Lines 143-147](../specs/mesh-mini-apps/spec.md#L143-L147) add the exact cross-history regression: a page at `http://hello.mesh`, a prior key at another node's gateway origin, and a dotted-name/raw-IP entry that must link out. This is stronger and more complete than enumerating the currently visible gateways.
2. **Discovery no longer contacts app hosts from the visitor's browser.** [Delta lines 40-52](../specs/mesh-mini-apps/spec.md#L40-L52) assign discovery to each node's hello service, and [lines 95-99](../specs/mesh-mini-apps/spec.md#L95-L99) make the browser-observable timing explicit. Entry documents remain tap-to-load under [lines 125-135](../specs/mesh-mini-apps/spec.md#L125-L135).
3. **Bridge size and numeric behavior are defined.** [Delta lines 157-170](../specs/mesh-mini-apps/spec.md#L157-L170) catch serialization failure, measure the cap as UTF-8 bytes of `JSON.stringify`, and require a finite numeric height before the shared clamp. [Lines 190-200](../specs/mesh-mini-apps/spec.md#L190-L200) cover non-finite, wrong-type, oversize, and unserializable cases.

## Regression and contradiction check

The amendments preserve the rest of the contract: manifests remain presentation data and cannot choose the entry origin; the browser re-validates node output; app markup stays out of the key-bearing document; card insertion remains explicit and cross-origin; and bridge send/receive checks still pin both the expected origin and the expected frame window. The fixed fetch path is distinct from the app entry path, so a TXT `path` cannot steer server-side I/O. The icon is the sole second fetch and remains under the same destination, method, redirect, time, and size rules.

One API detail remains for the act to make deterministic: `/api/apps` should bind each validated result to the current directory service identity without treating any server-returned entry URL or origin as browser authority. The browser should continue deriving and checking entry origin from the directory record. This follows the existing origin rules and shared-fixture task; it does not require a design change.

## Verdict

Accept. The round-1 security boundary and protocol ambiguities are closed, and the steered router-side discovery is sufficiently bounded to avoid a general-purpose fetch proxy or request-loop stall. Verification of the act should specifically prove direct record-IP connection, redirect refusal, streaming caps, cache invalidation on record mutation/removal, fetcher-private TLS relaxation, nonblocking `/api/apps`, and the measured aarch64 binary delta.
