## Blind pass — ten-line independent take

1. Pin one validator, and pin that it is the rule set the consumer already
   runs: `valid_relative_path` in `apps.rs` and `appPath` in `contract.ts`
   are today's two copies; publish must reuse, not add a third.
2. Pin omitted `path` as `/` at validation, and pin one storage/projection
   form so `{"app":{"v":1}}` and `{"app":{"v":1,"path":"/"}}` are the same
   record on the wire.
3. Pin no length ceiling of its own; the only size rule is whatever the
   record layer already has, and the reject then comes from that layer.
4. Pin `v` as integer `1` on name claims and `app=v1` byte-exact in TXT,
   because `contract.ts` compares `=== 'v1'`.
5. Pin what makes a marker "present": the `app` key. TXT `path=` is a
   documented free-form key on plain services today
   (`docs/join/publish/01-publish-a-service.md` Step 3, the ipp printer
   test with `path=/print`). Without `app`, `path` is opaque TXT and must
   not be validated, or publish becomes stricter than the consumer.
6. Pin rejection before any spool or lease mutation, and that a valid
   renewal without `app` clears the marker.
7. Pin proof of sameness: a shared vector set run by the Rust validator and
   by `contract.spec.ts`, like the manifest fixtures already do.
8. Refuse any publish rule the consumer does not have, and any consumer rule
   publish skips. Refuse touching the v1 signing preimage.
9. Note the existing drift: `apps.rs` rejects Unicode C1 controls
   (`char::is_control`), `contract.ts` rejects only C0 and DEL. A C1 vector
   in the shared set forces the two to agree.
10. Tradeoff: an unsigned marker lets whoever holds the name claim mark it as
    an app. Acceptable because the marker only changes presentation inside
    an origin the consumer derives itself, and cards stay sandboxed.

## Comparison and steelman

Both r1 findings are answered in the current text. The design and delta drop
the 256-byte ceiling and say so in words ("no separate publish-time length
ceiling"). Omitted `path` canonicalizes to `/` at storage, the directory
omits `txt.path` when the stored path is `/`, `{"app":{"v":1}}` has its own
scenario, and `--app-path` without `--app` has its own scenario. Storage as
`AppMarker { v: u8, path: String }` with `#[serde(default)]` on the outer
option is a sound shape for the old-record parse requirement, and hello
depends on the `mjolnir-mesh` library already, so "implemented once in
`mjolnir-mesh`" introduces no dependency cycle.

Steelman on the remaining gap: the delta says "validate the marker" and the
marker is defined as "version and an optional entry path", so a careful
reader infers that a bare `path` TXT is not a marker. That reading is
correct and it is the one the consumer takes. But design says "`txt.app` and
`txt.path` are validated by the same function" and tasks box 12 says
"validate TXT `app`/`path` in `publish_service`". An implementer following
those two lines literally will reject `mjolnir-meshd publish printer --port
631 --txt path=print`, which publishes fine today and which the consumer
never looks at. That is the acceptance's `if_false` branch, and it is the
same class of drift r1 caught with the ceiling. The fix is one sentence in
the delta and one scenario. It is a preparation defect, not an objection to
the architecture.

## Send-back findings

1. **Pin the marker gate.** On the control API the marker is present iff the
   `app` TXT key is present. When `app` is absent, `path` (and every other
   TXT key) is opaque and untouched, exactly as today. When `app` is present
   it must be `v1` byte-exact and `path`, if present, must pass the shared
   rule set. Add a scenario: a plain service published with `--txt
   path=print` and no `app` succeeds and lists as before. Reword design
   "Validation" and tasks box 12 to say the same.

## Notes for act (not conditions)

- `apps.rs` `is_mini_app` should call the new shared function and drop its
  private `valid_relative_path`. Otherwise the Rust tree keeps two copies and
  the design's "implemented once" is only true for the publish paths.
- Put a C1 control vector (for example U+0085) in `fixtures/app-marker/`.
  The living requirement says "control characters" without qualification, so
  the expected resolution is that `contract.ts` tightens to match the Rust
  rule, which is a change inside the living text, not to it.
- On name claims `v` is `u8`, so serde already refuses `"1"` and `1.0`. Add
  one vector for each so the JS side is held to the same answer.
- `path` after the marker is stored as `/` when omitted, and the directory
  drops `txt.path` for `/`. That means a claim with explicit `"path":"/"`
  and one with no path are indistinguishable downstream. That is the right
  call and the delta already says it; no change asked.
