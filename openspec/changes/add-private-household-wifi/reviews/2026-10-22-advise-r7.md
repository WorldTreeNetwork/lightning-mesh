## Blind take (written before opening design.md or tasks.md)

Sources: proposal.md, `specs/private-household-wifi/spec.md`, the living
`wifi-internet-uplink` and `node-connection-profiles` specs, the
household-network-management requirements, and the cited code
(`model.rs:34`, `uplink.rs:112`/`:227`/`:261`, `roam.rs:33`/`:122`).

1. Pin: the hostapd `wpa_psk_file` line format. "Exactly one line" is not enough. hostapd parses `<MAC> <passphrase|psk>`, so a bare passphrase fails to parse and the BSS does not come up.
2. Pin: who reads the secret file. The spec says root-only. On OpenWrt, hostapd may not run as root. Name the reading principal and the path it can see, or the resident SSID cannot start.
3. Pin: guest ingress source validation. Remote nodes reject INPUT by *source* class. A guest that spoofs a resident `10.42` source gets past that check. The guest-serving node has to drop guest-ingress packets whose source is outside its guest CIDR, and it has to key its forward deny on the ingress interface.
4. Pin: what a satellite guest gets. The return route is deferred, so the user journey should not imply working guest internet on a satellite.
5. Tradeoff: a stock OpenWrt config has `ula_prefix`, `ip6assign`, and `wan6`. If IPv6 refuses the guest, the guest feature is likely off on the whole fleet. That is acceptable for safety, but the change should say so.
6. Pin: `Plan` is one node. Guest enable is a multi-transaction sequence: the class goes on every node first, then the SSID. Name the order and the residual race.
7. Pin: the guest `ipv6=0` device needs a named guest bridge device, not a bare wlan ifname that netifd creates late.
8. Pin: the journal sidecar that snapshots the secret has the same mode as the secret.
9. Refuse: changing `guest_routes` is a meshd change, not a pure builder. Keep it scoped to the exclusion test.
10. Tradeoff: if any missing or stale node refuses the plan, guest enable is brittle on a flaky mesh. Accept that. Fail-closed is the right default for an "isolated" label.

## Steelman

**R7-1.** The author can say this follows the uplink precedent, whose
living spec also says "root-only file". The spec also leaves association
to hardware qualification on purpose. Both points are fair, but neither
covers this. Qualification is for radio behavior that cannot be known
from source. This one can be known from source. Upstream
`package/network/services/hostapd/files/wpad.init` (OpenWrt `main`,
read 2026-10-22) starts hostapd with `procd_add_jail hostapd`,
`procd_set_param user network`, `procd_set_param group network`, and
`no_new_privs 1` whenever `/sbin/ujail` and `/etc/capabilities/wpad.json`
exist. `wpad.json` grants only `CAP_NET_ADMIN`, `CAP_NET_BIND_SERVICE`,
and `CAP_NET_RAW`, with no `CAP_DAC_OVERRIDE` or `CAP_DAC_READ_SEARCH`.

On a default image, then, hostapd cannot open a `root:root 0600` file
under a root-only `/etc/mjolnir/secrets/` directory. It may also not see
that path inside its jail. The planned `wireless` would pass every unit
test and then fail deterministically on the first committed node. The fix
changes a SHALL ("root-only"), the file's owner and group, and probably
the snapshot/restore contract (for example a copy into a jail-visible
runtime path). That is cheaper to settle now than after `lpv`. I have
not checked which image the fleet runs. A one-line check on a node
(`ps w | grep hostapd`, plus `/sbin/ujail` present) settles it either way.

**R7-2.** The steelman is that fw4 forward rules are zone-scoped, so the
satellite's "deny forwarded guest destinations in the aggregates" is
naturally keyed on the guest ingress. Replies to a spoofed source also go
to the spoofed address, so any attack is blind. Both are true, but the
spec text does not say the forward deny is by ingress. The cross-node
INPUT reject is explicitly by *source* class. The design also allows
forwarding to destinations outside the aggregates, which includes house
addresses such as the gateway WAN, `wwan`, and recovery `192.168.1.1`.

A guest on a satellite can send a packet with source `10.42.5.23` (a
resident) to the gateway's WAN address. The satellite forwards it as
internet. The gateway's INPUT check by guest-source class does not match,
so the gateway accepts it from the mesh zone. Blind UDP to node services
is enough to break the "gate, not a label" claim.

The fix is one clause in the plan statement plus a test. It does not
render nftables, so it does not intrude on `mjolnir-mesh-nx1k`.

## Send-back items

### R7-1: Name the principal that reads the secret file (blocking, contract)

The spec and design say the PSK file is root-only, `0600`, under
`/etc/mjolnir/secrets/wifi/`. OpenWrt's `wpad.init` runs hostapd as
`network:network` in a ujail with no DAC-override capability. Resolve one
of these:

- (a) Pin owner `root`, group `network`, mode `0640`, a parent directory
  that `network` can traverse, and a path the hostapd jail can see.
- (b) Pin a root-owned canonical file plus an adapter-written runtime
  copy at a jail-visible path, and state which of the two the snapshot
  covers.
- (c) Verify on the fleet image that hostapd runs as root, unjailed, and
  record that fact with the evidence.

Change the spec SHALL "root-only" to match. Add a builder test that
asserts the planned owner, group, and mode.

The living uplink spec has the same exposure for `wpa_supplicant`, which
runs under the same `wpad.init` block. Filing a bead for that is outside
this packet's write paths, so the author or the conductor should file
it.

### R7-2: Guest ingress source validation (blocking, one clause plus a test)

The isolation statement must include both of these. First, the
guest-serving node drops packets arriving on its guest interface whose
source is outside that node's guest CIDR. Second, its forward deny is
keyed on the guest ingress interface, not on a source match. Without
these, the remote "reject INPUT from the guest-source class" rule can be
bypassed by spoofing a resident source.

Add a scenario: a guest sends with a resident source to a house node's
WAN address, and the plan denies it at the guest ingress. Add a builder
test that the isolated plan carries the ingress source check.
