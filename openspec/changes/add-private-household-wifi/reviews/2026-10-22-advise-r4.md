## Blind take (written before opening design.md or tasks.md)

Sources: proposal.md, `specs/private-household-wifi/spec.md`, the living
`wifi-internet-uplink` and `node-connection-profiles` specs, the
household-network-management requirement, and the cited code.

1. Pin: submission is typed against an adapter that snapshots and restores the secret file, like `ProvesUpstream` (`uplink.rs:261`). A pure builder alone does not keep `OpenWrtAdapter` from losing the secret on restore.
2. Pin: `Plan` is one `node_id` (`model.rs:34`), so the fleet INPUT reject is checked at build time on other nodes' revisions. Something must stop a later revision on a peer from dropping the guest class while a guest SSID is committed. Otherwise the gate is a time-of-check label.
3. Pin: a node that joins after a guest SSID is committed has no class. The spec only says it does not count for the next build. It must also say what happens to the committed "isolated" claim.
4. Pin: `roam::guest_routes` (`roam.rs:122`) admits any `10.42.0.0/16` neighbour outside `own_subnet`. A guest CIDR from `/subnets` lies inside that space. "Not installed or exported by roam" needs code or an owner.
5. Pin: "IPv6-enabled" needs a predicate. Stock OpenWrt has `ula_prefix` and `ip6assign` with odhcpd RA even when nobody turned IPv6 on.
6. Refuse: a key in `wireless`, an unkeyed hash of the secret, a builder-invented guest prefix, and a default hello.mesh exception.
7. Name: under "outside the aggregates stays allowed", the upstream ISP LAN behind the gateway is reachable by guests. Accepting that is fine, but it must be said.
8. Name: during a fleet cutover, one SSID name that is open on node A and `psk2` on node B confuses clients. Who orders the cutover?
9. Note: the `wpa_psk_file` line format makes a newline in the passphrase a line injection. Reuse the uplink `Passphrase` check.
10. Tradeoff: excluding guests from roam means guests lose sessions on node change. That is the right price for isolation without L2 bridging.

## Compare with design.md and tasks.md

Steelman first. The design answers most of the take, and answers it well:

- (1) The design returns a plan type that `OpenWrtAdapter` cannot submit. Its adapter contract makes hostapd re-read `wpa_psk_file` on apply and on restore. Answered.
- (6) Answered: the key is absent, there is no unkeyed hash, the CIDR is a `/subnets/{cidr}` input, and the default plan has no hello.mesh exception. The 6 GHz refusal is a good catch I did not have.
- (7) Answered explicitly: the upstream LAN is internet for this change.
- (8) The cutover name is an input owned by `mjolnir-mesh-lpv`. This change does not write radios. Acceptable here.
- (9) `Passphrase::new` (`uplink.rs:115`) already admits only `0x20..=0x7e`, so a newline cannot reach the file. The design should say it reuses that type. This is a note, not owed.
- (10) Matches "guests do not roam; they re-DHCP on the node they join".
- (2) The design has the right sentence: "Restoring away the reject while any node still has the guest SSID committed is refused." Automatic engine restore cannot drop the class. A guest SSID is only enabled after the class is committed on every peer, so every later peer revision's predecessor already carries it. The automatic path is therefore safe by ordering.

What still does not hold:

### R4-1. The peer-drop refusal is in the design but not in the contract

Spec §"Guest isolation is a gate" gates the build only. It has no SHALL
that refuses a later revision on a peer that removes a guest CIDR from
that peer's committed class while a guest SSID on that CIDR is committed.
Nothing in tasks owns it either. This is the only thing that turns a
build-time check into an invariant, because `Plan` has one `node_id` and
no cross-node precondition. "Restoring away" is also the wrong verb. The
risk is an owner-authored revision from any builder (uplink, profile,
this one) that rewrites `mjolnir` without the class. A rollback is not
the risk. Owed: a spec SHALL plus scenario, worded for any revision. Also
a test in the builder task.

The same section of design.md calls the class "the committed fleet guest
plan". No fleet plan exists in the transaction model. The spec defines
the class as the CIDRs in each node's committed `mjolnir` config. Owed:
one definition. Use the spec's.

### R4-2. The roam SHALL has no owner

The spec says guest prefixes "SHALL NOT be installed or exported by
roam". `guest_routes` filters only on `mesh_space` (`10.42.0.0/16`),
`own_subnet`, NUD, and association. Suppose a guest-CIDR address shows
up on `br-lan`, either from a stale lease after an SSID switch or from a
static address a resident set. Then roam installs a proto-158 `/32` for
it and the address follows that resident's node. The design states the
outcome but no task implements it, tests it, or defers it. Owed: one of
two fixes. (a) Add a task and a test that `RoamInputs` excludes the
committed guest-source class. This touches `crates/` in a build slice,
not in this advise. (b) Narrow the SHALL to what this change controls
and name a meshd bead for the roam exclusion.

### R4-3. "IPv6-enabled" has no predicate

The design says the flag is read from the committed `network` and
`mjolnir` config, and that unknown refuses. It never says which keys mean
enabled. A builder that reads only a `mjolnir` flag would call a stock
`network` with `globals.ula_prefix` and `lan.ip6assign` "disabled". The
guest would then get RA and SLAAC with no v6 deny. Owed: pin the
predicate. The minimum is any of `ula_prefix`, `ip6assign` on any
interface, `wan6` or a `dhcpv6` proto, or odhcpd `ra` or `dhcpv6` server
on a client interface. Also pin that the guest interface itself carries
no `ip6assign`. Add a test whose stock-OpenWrt `network` fixture is
refused.

### R4-4. A post-commit join leaves the label standing

"A newly joined node SHALL NOT count as covered" constrains the next
build only. A node that joins after a guest SSID is committed lacks the
INPUT reject. If that node has addresses outside the aggregates, guests
reach its INPUT. Examples: it exports a default route, or it has a WAN or
`wwan` address. The committed plan still says `isolated`. That contradicts
"a gate, not a label". Owed: one spec sentence choosing one of two rules.
(a) A joining node's admitted config carries the committed class before
it exports routes. (b) The isolated claim is withdrawn and recomputed
until the node commits the class. Either rule needs a bead pointer for
the join side. `add-zero-touch-join` is out of this change's paths, so
point at it; do not edit it.

## One tradeoff I accept

Guests are excluded from roam and re-DHCP per node. That costs live
sessions on node change. It is the right price: isolation stays a routed
property with no L2 bridging and no mesh-wide guest `/32`s.

## Verdict

Send-back. The design is sound and close. The four boxes are wording
and contract alignment plus one predicate. None of them is a redesign.
The Fresh advise box stays open.
