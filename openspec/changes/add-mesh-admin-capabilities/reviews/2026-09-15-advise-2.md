## 1. Blind pass (written from Why, living spec, portal.rs and identikey-capability-v1 only — before opening codec-profile.md / design.md / tasks.md)

1. Pin ONE canonical, self-delimiting byte encoding (canonical CBOR per IdentiKey
   §3.4) for the signed request/proof tuple; reject any non-canonical re-encoding —
   no field reordering, no optional-field or length ambiguity that lets two requests
   share a hash or one byte-string parse two ways.
2. Pin the signed holder-proof tuple as (token-identity, verifier-chosen nonce,
   audience, optional response-key) with an explicit domain-separation tag so a
   signature can never cross contexts (node A vs B, redeem vs admin-op).
3. Define "token identity" concretely: it must bind the sealed/received token bytes,
   not a re-serialized malleable form; otherwise altered-holder/replay detection is
   undefined (IdentiKey §7.1 defers this to Mjolnir — the local pin must own it).
4. Fingerprint = Blake3 over the self-describing pubkey {alg,key} per auth-challenge
   §5, in its own namespace — never SHA-256, never raw-Ed25519 preimage, never
   conflated with the recrypt identity envelope or content-address Blake3.
5. Holder is a CHECK; verifier computes the fingerprint from the presented key and
   binds it only after the signature verifies; possession of bytes is never
   authorization; fail closed (portal.rs: public identity is not administration).
6. Reject any minted token asserting a holder/time/authority fact; monotonic
   attenuation only narrows — a narrower owner op passes, widen/other-node/other-op
   fails.
7. Pin a closed algorithm allowlist; reject unknown alg tags; no downgrade; the
   holder-proof scheme must match the presented key's declared alg.
8. Time and authority-epoch are trusted verifier facts, never token-asserted; a
   spoofed clock or stale epoch must NOT grant runtime; a caller wall-clock is not
   evidence; this library cannot *prevent* replay (no durable state) and must say so.
9. Refuse: raw/re-serialized token identity, unsalted secret digests, open alg
   field, token-asserted time, any SSH/role-label fallback on denial (typed denial).
10. Tradeoff: freezing a byte-level profile before upstream vectors exist
    (`ikp-6yz.2`) creates reconciliation debt — acceptable only if the pin is
    honestly marked local/draft and ships its own conformance fixtures.

## 2. Contrast — the pin steelmanned against the blind take

The blind points are concerns the author had to answer, not a rival design. Every
one is answered concretely, and several are answered more sharply than the blind
take demanded.

| Blind concern | Answered by codec-profile.md |
|---|---|
| 1 canonical bytes | Definite 10-element CBOR array; smallest-int + definite-length only; **decode → re-encode with the one encoder → compare exactly to input**; reject trailing bytes, indefinite/nonminimal forms, >1024 B before allocation; closed schema (no floats/tags/maps/null/optional/user text). This is the gold-standard anti-malleability path. |
| 2 domain/field binding | Signed array begins `["lightning-admin/request", 1, …]`; binds house, node (audience), epoch, operation, arguments, token_identity, target_challenge, request_id. Domain+version are inside the signed bytes; "the versioned array is its domain"; deliberately **not** the auth-challenge signing domain (no cross-protocol reuse). |
| 3 raw token identity (B1) | `BLAKE3("lightning-admin/token/v1" ‖ 0x00 ‖ raw_biscuit_bytes)` over the exact received bytes, base64-decoded but **not parsed/re-serialized** before hashing; attenuation/sealing changes identity → fresh holder signature; explicitly NOT a revocation-lineage id. |
| 4 fingerprint namespace (B4) | `BLAKE3(CBOR({"alg":"ed25519","key":bstr32}))`, fixed key order, per auth-challenge §5; algorithm-committing; raw-key/alg-alias rejected; recrypt-envelope fingerprint named as a different namespace not to substitute. |
| 5/7 possession ≠ authorization | Result type is `VerifiedHolderProof`, explicitly **not** `AuthorizedRequest`: "establishes only possession of a key for those bytes." Codec "must not expose an execute/authorize API"; slice has "no public authorization method." |
| 6 monotonic / reject minted facts | Auth-engine pin: reject reserved verifier-fact assertions in any block incl. rule heads that derive them (inspect parsed structures, not substrings); authority-only rights, appended blocks narrow only. (Engine-scoped, noted below.) |
| 7 crypto APIs | `ed25519-dalek =2.2.0`, `VerifyingKey::from_bytes` + **`verify_strict`** (rejects malleable/small-order sigs), reject weak keys, no permissive verify, no caller-supplied proof bool. `minicbor =0.26.5` with honest "not a dCBOR claim." |
| 7 allowlist | Exactly ed25519 / 32-B key / 64-B sig; P-256 & PQ unsupported, "not silently downgraded"; extending alg needs a reviewed pin. |
| 8 no faked time/replay | "this codec slice must not fake them to claim the full grant verifier exists"; "Do not use `AuthorizerBuilder::time()` as trusted time evidence: it reads the clock"; absolute validity fail-closed until authenticated time lands; replay reservation is b6j.2, no permissive in-memory fallback. |
| 10 reconciliation debt | Header: "local pin … not upstream conformance"; upstream tuple/vectors "still owed to `ikp-6yz.2`"; source revision pinned (`093ceb1…`). Honest per the packet anchor. |

**Acceptance test (`contrast`) is met within slice scope.** The pin distinguishes a
valid narrower owner-authorized operation from the attack classes, with honest
boundaries about what the codec cannot do alone:

- **valid narrower op** — operation/node/args are in the signed bytes; a diagnostics
  proof cannot be reused for apply (any field change fails the signature); Biscuit
  attenuation narrows the ceiling (engine).
- **altered holder / altered token** — `token_identity` in the signed request is
  checked equal to `BLAKE3` of the *actually presented* raw token, so a signature
  bound to token T cannot be presented with token T′; attenuation forces a fresh
  signature.
- **altered request field** — decode/re-encode-compare + `verify_strict` over the
  canonical bytes.
- **membership / role / association** — not representable; no directory/hostname/role
  lookup constructs context (design); authorization needs an owner grant (portal.rs
  invariant upheld).
- **untrusted issuer / stale authority / replay** — correctly **deferred, not faked**:
  issuer pins, epoch-floor, trusted time and one-use reservation are engine/b6j.2
  obligations the slice refuses to stub permissively. That refusal is the honest
  boundary the packet requires, not a gap.

The possession/authorization seam — the Why's central demand — is enforced by a
**type distinction**, not a boolean, which is the strongest available form.

## 3. Findings for beads — implementation & integration obligations (concrete, not policy)

None of these is a spec contradiction or a missing constraint that prevents using
this pin as the downstream trust contract, so none blocks acceptance of the pin.
They are concrete obligations to record against `mjolnir-mesh-ai0.1.1` (codec) and
the future engine packet; record in beads, no task checkboxes.

- **F1 (codec, must-test) — canonical gate precedes/co-gates signature.** The
  signature MUST be verified over the canonical received bytes AND the
  decode/re-encode equality MUST gate; never verify a signature over a *normalized*
  form of non-canonical input. Profile says "no normalization of hostile bytes
  followed by verification" — add an explicit negative fixture: non-canonical
  encoding carrying an otherwise-valid signature is rejected by the canonical gate.
- **F2 (codec, must-test) — operation↔arguments arity coupling.** Enforce op 0 ⇒
  args exactly `[]` and op 1 ⇒ args exactly `[plan_id, expected_revision,
  plan_digest]` (3×bstr32). Negative fixtures: op 0 with non-empty args; op 1 with
  wrong arity/element length; unknown operation.
- **F3 (codec, must-test) — epoch Datalog boundary.** `authority_epoch` is
  `0..=i64::MAX` for Biscuit Datalog compatibility; the decoder MUST reject a uint >
  `i64::MAX`. Include `0`, `i64::MAX`, and `i64::MAX + 1` in the integer-boundary
  fixtures.
- **F4 (codec↔engine integration) — shared exact byte buffer.** `token_identity`
  binds the raw received token bytes (unparsed). The engine (`Biscuit::from`) MUST
  verify the chain over the *same* received buffer, not a re-serialized form, or
  identity and verification can diverge. Record this as an integration precondition
  in the engine packet so `to_vec()`/re-serialization is never substituted for the
  hashed bytes.
- **F5 (codec, honest-fixture) — local fingerprint vectors.** auth-challenge §5 has
  no upstream test vectors yet; the fingerprint's CBOR map (definite, key order
  `alg` then `key`, minimal) MUST ship local golden fixtures marked
  local-until-`ikp-6yz.2`-reconciliation, matching the doc's own honesty clause.
- **F6 (codec, defense-in-depth) — reject, don't merely ignore, a `holder` fact.**
  IdentiKey §7.1 rejects a minted token asserting a `holder` fact outright. The
  slice hashes raw token bytes and does not parse them, so this enforcement lands in
  the engine, not the codec — record it against the engine packet (with `time` /
  `epoch` / count facts treated the same) so the r1 hardening note is not lost.
- **F7 (engine, scoped-out but positively noted)** — the engine pins are sound and
  correctly out of this slice: reject third-party blocks in v1 (resolves r1 B3),
  ≤16 blocks / 64 KiB, authorizer limits (1024 facts / 64 iters / 20 ms, limit ⇒
  deny), no `AuthorizerBuilder::time()` as trusted time. These must be confirmed
  against the pinned `biscuit-auth =6.0.0` APIs in the engine packet before coding.

## 4. Verdict rationale

Accept the byte-level profile and the `ai0.1.1` codec/holder-proof slice as ready to
implement. Within its declared scope the pin makes every distinction the acceptance
contrast requires, resolves r1's B1 (token identity) and B4 (fingerprint/allowlist)
concretely, and is honest where it cannot go alone: it introduces **no** faked
trusted-time or replay surface — the codec slice has no time/replay API at all, and
the profile explicitly forbids a permissive stand-in and forbids clock-reading as
trusted time. Possession is separated from authorization by a type, parse ambiguity
is closed by a closed schema plus decode/re-encode-equality plus a pre-parse size
cap, and the crypto is pinned to `verify_strict` with exact-version dependencies and
a closed single-algorithm allowlist. The F1–F7 items are implementation/test and
integration obligations the profile already gestures at, not missing constraints or
contradictions — routing them to beads against ai0.1.1 and the engine packet is the
correct spec↔implementation seam. The upstream-vector gap (`ikp-6yz.2`) is recorded
as reconciliation debt, not passed off as upstream conformance.

No product code, deploy, fold, or commit performed; only this review file written.
