## Independent take (blind)

1. Pin the public origin to an owner-key-derived label so a change of owner necessarily changes the browser origin.
2. Pin one configured delegated zone and reconcile its dnsmasq forward and rebind exception additively beside the existing `.mesh` entries.
3. Require every locally answered alias to come from an owner-signed record verified by each consumer, not trust in the ingesting node.
4. Pin the signed bytes, field order, encoding, and envelope exactly enough that independent implementations produce identical verification input.
5. Refuse replay, rollback, equivocation, and cross-key label collisions; ambiguous state must resolve to no answer, never a winner.
6. Preserve collision evidence across expiry, withdrawal, restart, and compaction so a later key cannot inherit an earlier key's origin.
7. Bind ACME authorization to the exact FQDN, TXT digest, account, CSR key, nonce, and short expiry while keeping the TLS private key host-local.
8. Constrain DNS answers to validated mesh addresses and keep offline resolution independent of the public authoritative service.
9. Preserve `http://hello.mesh`, captive-probe byte behavior, and unrelated dnsmasq configuration while exposing certificate failure and remaining validity honestly.
10. Tradeoff: public-CA browser trust introduces internet-time issuance and DNS-adapter dependence, acceptable only if renewal is opportunistic and the adapter/domain is replaceable.

## Steelman and comparison

The amended design answers the blind concerns as a coherent end-to-end contract. Key-derived app and node labels preserve browser-origin separation; exact-suffix forwarding and rebind exemption extend the existing `.mesh` dnsmasq seam without broadening the parent zone; and verified owner-signed alias records remain locally useful while the internet and public adapter are absent. The owner authorization key, host-local TLS key, and CSR binding have distinct roles. The operational cost is durable collision history and an online issuance path, which is the correct availability-for-origin-integrity tradeoff because `.mesh` HTTP and local alias resolution remain available.

The living mini-app spec makes origin identity security-sensitive: assertion audiences, approvals, framing checks, and navigation are bound to an exact origin. This change preserves that invariant by allocating a new key-qualified hostname on normal ownership change and refusing a truncated-label collision instead of letting two owners share one origin. It also preserves the captive front door and current additive dnsmasq ownership model.

## r2 blocker closure

1. **Byte-exact serialization is closed.** Both signed record families now specify the domain line, UTF-8 compact JSON, zero whitespace, fixed field order, unescaped solidus, shortest-decimal integers, mandatory-only string escaping, lowercase fixed-width key/signature encodings, and a three-line LF envelope. The alias payload is written out in full, and issuance names its ordered fields in both design and delta. Golden-byte and malformed-encoding vectors are explicitly owed. Independent signer and verifier implementations therefore no longer need to choose among equivalent JSON serializations.

2. **Durable collision memory is closed.** AliasTable retains the full owner public key in a per-label collision set forever across expiry, tombstone, compaction, and process restart. The issuance adapter uses the same durable history. A tombstone stops the record answering but does not erase its collision evidence, so a later colliding key cannot inherit the origin. Equal-sequence, different-payload alias records also fail closed rather than depending on iteration order.

The acceptance contrast is satisfied: independent implementations have one signed byte contract, and a tombstoned colliding owner remains permanently relevant to both resolution and issuance. Implementation vectors should include envelope/payload owner-key mismatch alongside the already required malformed, collision, wrong-owner, and wrong-CSR cases; that is verification coverage, not an architectural blocker.
