## Independent take (blind)

1. Pin every HTTPS hostname to the authorization key that owns the published app or node record, not to a mutable display name or operator assignment.
2. Pin a signed alias-record contract with explicit signer, covered fields, expiry, replacement rules, and a deterministic lookup from FQDN to mesh address.
3. Keep the owner authorization key distinct from the host-local TLS private key; ownership may authorize a CSR but must never require exporting or reusing either secret.
4. Refuse hostname reuse across owners, including after withdrawal, and fail closed if truncated key labels collide rather than choosing a winner or sharing an origin.
5. Forward and exempt from DNS rebinding only the configured delegated suffix; never claim its parent zone or loosen private-address checks globally.
6. Pin offline DNS behavior, address eligibility, TTL/expiry, and failure semantics so stale, unsigned, conflicting, or out-of-range aliases cannot resolve.
7. Pin issuance authorization as a versioned domain-separated signature over byte-exact canonical fields binding FQDN, record state, ACME account, CSR SPKI, nonce, and expiry.
8. Refuse replay and substitution across hostnames, accounts, CSRs, owners, or meshes; verification must reject unknown versions, malformed encodings, and expired requests.
9. Preserve origin isolation in the mini-app surface: assertions, approvals, cooldowns, embeds, and navigation must use the key-qualified HTTPS origin without silently inheriting `.mesh` state.
10. Tradeoff: an 80-bit human-manageable label is acceptable only with deterministic collision detection and denial; availability loses to never merging two owners into one browser origin.

## Steelman and comparison

The amendment materially improves the change. It now owns `mjolnir-https-alias:v1` consistently across proposal, design, delta, and tasks. It cleanly separates the label's owner authorization key from the host-local TLS leaf key and binds issuance to the CSR SPKI. It also makes the compact 80-bit label an explicit availability-for-isolation tradeoff, with fail-closed checks in both AliasTable and the DNS adapter. The exact-suffix dnsmasq rule, unchanged `http://hello.mesh`, per-router keys, no wildcard/shared-key path, and best-effort replaceable adapter remain coherent.

Compared with the prior send-back:

- Record ownership is closed: this change owns the signed resolution record and `ai0.9` supplies only reusable integrity primitives.
- Owner key versus TLS key is closed: the normative delta and design now distinguish them and include a wrong-CSR-key scenario.
- Collision handling is directionally closed for simultaneously known records, but durable collision memory is not yet pinned.
- Issuance fields and their order are pinned, but the signed byte encoding is not yet byte-complete.

## Blocking findings

1. **“Canonical JSON, keys in this order” is not one interoperable byte encoding.** JSON permits insignificant whitespace and multiple equivalent string encodings (notably escaped versus unescaped `/` in the ACME account URL); “canonical” does not name a standard, and the listed order is not RFC 8785/JCS order. Independent signer and adapter implementations can therefore serialize the same fields to different signed bytes. The alias record has the same ambiguity. Pin UTF-8 plus an exact serialization rule (including object punctuation, no whitespace, string escaping, and integer form), or publish normative golden signed-byte vectors that fully determine it. Also pin the issuance envelope that carries the full owner public key, signature, authorization payload, and CSR to the verifier. Until then a worker still has to guess encoding at the authorization boundary.

2. **Fail-closed collision handling has no retention lifetime, so the no-recycled-origin invariant can lapse.** The adapter checks for “any other retained key,” while AliasTable refuses only when it can evaluate two verified records. The change does not say whether a full owner key remains collision-relevant after its record expires, is tombstoned, is compacted, or the process restarts. Forgetting K1 and later accepting colliding K2 would hand K1's browser origin to K2. Pin durable per-label owner-key history (including tombstoned owners) for both resolution and issuance, or narrow the claimed invariant and choose a label scheme that does not depend on remembered collision state. While specifying record convergence, also define equal-`seq` conflicting payloads as fail-closed rather than leaving AliasTable iteration order to choose an address.

With those two contracts explicit, the amended architecture is ready: AliasTable, issuance verification, and router TLS can then be implemented without serialization guesses, shared certificate keys, or a path that revives a collided origin.
